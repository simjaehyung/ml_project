⚖️
Precision과 Recall — 두 가지 실수의 비용
모델은 두 종류의 실수를 한다. 어느 실수가 더 비싼가에 따라 임계값을 선택한다.
False Positive (헛알람)

취소 안 할 손님인데
"취소 위험" 경보를 울림

비용: 불필요한 오버부킹 대응,
매니저 시간 낭비

Precision ↑ = 헛알람 적음
경보 울린 것 중 진짜 취소 비율
False Negative (놓침)

취소할 손님인데
"안전" 판정을 내림

비용: 빈 방 손실,
수익 기회 소멸

Recall ↑ = 놓치는 취소 적음
실제 취소 중 잡아낸 비율
우리 선택 기준

빈 방 손실 vs 오버부킹 보상
중 어느 쪽이 더 비싸냐?

일반적으로 빈 방이 더 비쌈
→ Recall 조금 더 중시
→ 임계값을 낮게 설정

Week 4에서 정확히 결정
💡 F1 = Precision과 Recall의 조화평균. 둘 다 높아야 F1이 높다. 하나만 극단적으로 올리면 다른 쪽이 망가진다.

📚 개념 설명
✁
임계값(Threshold)이란?
모델은 각 예약에 취소 확률 0~1을 출력한다.
임계값은 "이 숫자 이상이면 취소 위험 예약으로 분류하겠다"는 기준선이다.
임계값 낮게 (0.4)

취소 확률 40% 이상이면 모두 경보
→ Recall ↑ (놓치는 취소 없음)
→ Precision ↓ (안 취소하는 손님도 경보)
"헛알람 많지만 취소 놓치지 않는다"
임계값 높게 (0.7)

취소 확률 70% 이상만 경보
→ Precision ↑ (경보 대부분 진짜 취소)
→ Recall ↓ (낮은 확률 취소는 놓칠 수 있음)
"헛알람 없지만 일부는 놓친다"
💡 빈 방 손실(FN, 취소 놓침) vs 오버부킹 보상(FP, 헛알람) 중 어느 비용이 더 크냐에 따라 임계값을 선택한다. Week 4에서 walk_rate 곡선 보고 확정.

📚 개념 설명
🚶️
walk_rate란? — Flexi 시스템의 핵심 지표
호텔이 오버부킹(정원 초과 예약)을 받으면, 실제로 손님이 다 왔을 때 일부를 돌려보내야 할 수 있다.
walk_rate = Flexi 풀로 받은 예약 중 실제로 돌려보낸(walk) 비율
walk_rate 높음

Flexi 슬롯을 너무 많이 열었음
예상보다 취소가 적어서
실제 손님이 많이 왔는데
방이 부족해 돌려보냄

손님 불만, 보상 비용 발생
walk_rate 낮음 (목표 < 2%)

취소 예측이 정확해서
오버부킹 슬롯이 적절히 채워짐

빈 방 손실 줄이면서도
손님을 돌려보내는 일 없음
💡 우리 프로젝트에서는 Pool A(실제 취소한 예약)만 있다. walk_rate는 "임계값을 높일수록 낮아지는가?"를 시뮬레이션으로 확인한다. Pool B(Flexi 전환 수요)는 반사실적이라 사용하지 않는다.

📚 개념 설명
🔄
Flexi 시스템이란? — 취소를 역이용하는 운영 전략
호텔은 취소가 발생하면 빈 방이 생긴다. Flexi 시스템은 이를 역이용해 "어차피 취소할 것 같은 예약 자리에 추가 예약을 받는다"는 전략이다.
Pool A (우리가 쓰는 것)

실제로 취소된 예약들의 데이터
이 패턴으로 취소 확률 학습

"이 예약은 취소될 가능성이 높으니
이 자리에 Flexi 예약을 추가로 받자"

✓ 실데이터 기반 → 방어 가능
Pool B (우리가 안 쓰는 것)

Flexi로 전환한 예약이
실제로 왔을 경우의 수요

문제: 이 수요가 실제로 존재하는지
어떤 수치도 구조적으로 증명 불가

✕ 반사실적 수요 → 방어 불가
우리의 접근 (Policy-Level DSS)

매니저가 임계값·슬롯 수를
설정하면 시스템이 자동 실행

개별 예약 판단 아님
→ 책임 전가 아닌 정책 설계

✓ Talluri & van Ryzin 2004
💡 walk_rate: Flexi 슬롯으로 받은 예약 중 실제로 돌려보낸 비율. 취소 예측이 정확할수록 walk_rate ↓. 목표: walk_rate < 2%. 이것이 우리 모델의 실제 운영 가치 증명 포인트.
Part 2 — Beyond Cancellation

취소 예측이 풀 수 있는 운영 문제 3개

💰
채널 실효 수익 분석 (Channel Effective Yield)
김나리 · Week 5
effective_adr = ADR × (1 − cancel_rate) → Online TA가 ADR 높아도 취소율이 높으면 실효 수익이 낮다. "Direct 채널이 실제로 더 수익적이다"를 데이터로 증명. 현재 SHAP 6위: market_segment_Online TA (0.371) → 취소 올림 확인됨.
⭐
예약 품질 점수 (Booking Quality Score)
심재형 · Week 5
BQS = w1·ADR + w2·stays + w3·special_requests − w4·cancel_proba → 취소 확률만으로 우선순위를 잡으면 안 된다. SHAP에서 total_of_special_requests가 #3 (취소 낮춤) 확인 → BQS 가중치 근거 확보됨.
🍽️
음식 낭비 예측 (Food Waste Prediction)
이고은 · Week 6
food_risk = cancel_proba > 0.65 & meal in [HB, FB] → 기존 도구는 사후 모니터링. 우리는 사전 예측으로 발주 전 조정. EU CSRD 2024 식품 낭비 보고 의무화 맥락과 맞물림.
