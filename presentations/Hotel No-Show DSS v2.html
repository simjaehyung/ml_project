우리가 정의하는 문제 — 두 층위
LAYER 1 · 기존 예약
"체크인이 다가오는 예약들 중,
오늘 먼저 확인해야 할 예약이 어떤 건지
어떻게 아는가?"
LAYER 2 · 신규 예약
"들어오는 예약을
위험도에 따라 Standard와 Flexi로
어떻게 분기할 것인가?"
기존 방식우리 방식
예약 1건 입력 → 확률 조회 오늘 예약 전체 → 위험 순위 리스트
매니저가 직접 골라서 확인 시스템이 먼저 걸러서 제시 + 행동 권장
신규 예약 → 일괄 Standard 배정 신규 예약 → 위험 기반 Standard / Flexi 분기
하나의 위험 예측 엔진이 두 문제를 동시에 해결한다. 기존 예약에서는 우선순위를, 신규 예약에서는 상품 분기를.

Layer 2 — 정밀 오버부킹
기존 — 블라인드 오버부킹
과거 평균 취소율 35%
→ 전체 예약의 35%를 일괄 초과 판매
→ 어느 예약이 취소될지 모르고 찍는 것
Flexi — 정밀 오버부킹
모델 → "이 예약들이 취소될 가능성이 높다"
→ 그 자리에만 Flexi 예약 추가 판매
→ 예측 정확도가 높을수록 walk 없이 방을 채운다

  • 1
    시간 기반 Train/Test Split 마지막 6개월(2017.03–08)을 Test로 고정. 무작위 분할은 미래 정보 오염으로 성능을 과대평가한다.
  • 2
    누수 컬럼 5개 제거 reservation_status (타깃 동치) · reservation_status_date · assigned_room_type 외 2개. 체크인 이후에야 채워지는 값은 모두 제거.

    평가 지표: PR-AUC (메인) 빈 방 손실(FN)과 오버부킹 보상(FP) 비용이 비대칭. 임계값 선택에 직접 활용 가능.
  • 4
    TreeSHAP 선택 샘플링 없이 정확 계산. XGBoost·LightGBM 전용. Phase 2에서 LIME 비교 실험 예정.
