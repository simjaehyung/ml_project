## 1. 사전 준비 (발표 30분 전 완료)

### 1.1 서버 기동 순서 (반드시 이 순서)

세 개 터미널을 띄운다. **DSS → PMS → Next** 순서. (DSS가 먼저 떠 있어야 PMS가 예약을 밀어넣을 때 받는다.)

```powershell
# ── 터미널 1 : DSS (FastAPI, LightGBM 실모델) port 8001 ──
# 프로젝트 루트(07_Hotel_DSS)에서
uvicorn api.main:app --port 8001
# 확인: http://localhost:8001/api/v1/dashboard/summary 가 JSON 반환

# ── 터미널 2 : PMS (손님 에이전트용 mock) port 3001 ──
uvicorn app_pms.pms_mock:app --port 3001
# 확인: http://localhost:3001/admin/stats 가 JSON 반환

# ── 터미널 3 : Next.js 앱 port 3000 ──
# hotel-dss-app 디렉터리에서
npm run dev
# 확인: http://localhost:3000/dashboard 가 뜸
```

> 주의: `lib/api.ts` 는 **8001**, `lib/pms-api.ts` 는 **3001** 고정. 포트 틀리면 앱이 빈 화면.
> `--reload` 는 발표 중엔 빼라(파일 저장 시 서버 재시작으로 데모 끊김).

### 1.3 시드/속도 고정 (재현성)

- **시드 고정**: 라이브 추론 데모(예약 1건 → 위험점수)를 곁들일 경우, `api/main.py` 의 `random` 시드가 발표마다 달라지면 멘트 숫자(예: SHAP top3)가 흔들린다. 발표 전 1회 dry-run 해서 **나오는 숫자를 멘트에 박아둔다**(검증 숫자는 `docs/week6_devA_demo_script.md` 참조: 위험 0.94, 할인 16.4%→손님 14.3%).
- **재생 속도 고정**: 허브 "자라남" 재생 속도는 **2분 안에 wk 27→141이 한 바퀴** 돌도록. 너무 빠르면 점 누적이 안 보이고, 너무 느리면 발표 시간 초과.
  - 재생 뷰 URL: **`http://localhost:3000/dashboard/hub`** / 속도 파라미터: **컨트롤바 0.5×·1×·2×·4× 버튼(키 1/2/3/4), 기본 1× ≈ 114초 완주.** 발표 2분 타깃이면 1× 그대로.
  - **키보드:** `Space` 재생/정지 · `c` 캡쳐모드(컨트롤 숨김) · `f` 풀스크린 · `r` 처음으로 · `1/2/3/4` 속도. `?capture=1` 쿼리로 진입 시 캡쳐모드 자동.
  - **seek(정지프레임):** 컨트롤바 슬라이더/숫자입력에 wk(27~141) 직접 입력. 캡쳐 권장 seek 값:
    | 캡쳐 | seek wk | 잡히는 프레임 |
    |------|:------:|---------------|
    | C1 빈 허브 | **27** | 카운터 0 부근, 곡선 바닥 |
    | C2 점 누적 초기 | **40** | 카드 유입 시작, 곡선 미분화 |
    | C3 교차 직전 | **70** | LR이 아직 LightGBM 앞섬 |
    | **C4 W 전환** | **84** | 앰버 글로우 + "W≈5.4만·84주" 라벨 (덱 클라이맥스) |
    | C5 위험 3색 분포 | **100** | brick/ochre/forest 분포바 + train 누적 |
    | C6 0.820 정점 | **106 이상(예: 120)** | "학습 완료" + 라인끝 0.820/0.782/0.387 라벨 고정 |
- **풀스크린**: 브라우저 F11 풀스크린, 북마크바·확장프로그램 숨김, OS 알림 OFF(Windows 집중 지원 ON).
- **녹화**: 1.1~2절 전체를 OBS 또는 Xbox Game Bar(`Win+G`)로 **사전 녹화**해 둔다 → 4절 백업 mp4.

## 3. 슬라이드 캡쳐 계획 (어느 프레임 → 어느 슬라이드)

> 라이브가 메인이지만, **슬라이드에는 정지 캡쳐를 박아** 라이브 실패 시에도 스토리가 끊기지 않게 한다.
> 아래 6컷을 2절 녹화/라이브에서 딴다. 최소 **4컷(C1·C4·C6 + C3)**, 여유되면 6컷.

| 캡쳐 | 프레임 (2절 #) | 들어갈 슬라이드 | 슬라이드에서의 역할 |
|------|----------------|-----------------|----------------------|
| **C1** 빈 허브 | #1 (0:00) | **S2** (문제 제기) | "시작점: 데이터도 모델도 없음" |
| **C2** 점 누적 초기 | #3 (0:25) | **S2** (보조) | "예약 = 점, 색 = 위험" 개념 설명 |
| **C3** 교차 직전 | #4 (0:45) | **S3** (성장 곡선) | LR이 아직 앞서는 구간 |
| **C4** W 전환 | #5 (1:05) | **S3** (핵심 컷) | **5.4만 건에서 LightGBM 추월** — 덱 전체의 클라이맥스 |
| **C5** 위험 3색 분포 | #6 (1:30) | **S4** (위험 우선순위) | brick/ochre/forest 분포로 액션 연결 |
| **C6** 0.820 정점 | #7 (1:50) | **S4** (결과 확정) | 최종 PR-AUC 0.820 vs Dummy 0.387 |

**캡쳐 규격:** 1920×1080, PNG, 풀스크린 상태에서. 파일명 `cap_C1_empty_hub.png` … `cap_C6_peak_0820.png`, `presentations/captures/` 에 저장.
**덱 액센트 일치 확인:** 캡쳐 안의 곡선/점 색이 덱 팔레트와 어긋나지 않는지 — 인디고 #1B3A8F, 앰버 #8A5A0F, 위험 brick #B23A2E / ochre #B8862B / forest #3F7A52.

## 4. 실패 백업 3단계

|------|--------|------|

## 부록 — 멘트에 박을 확정 숫자 (growth_curve_agg.csv 근거)

| 지점 | 값 | 출처 행 |
|------|-----|---------|
| Dummy 바닥 | PR-AUC **0.387** | 전 구간 고정 |
| LR 수렴 | ~**0.78** | wk≈100, LR 0.780 |
| W 전환점 | **wk≈84 / n≈53,615 (5.4만)** 에서 LightGBM > LR | cumulative wk84: LGBM 0.799 > LR 0.781 |
| 최종(풀) | **0.820** | LightGBM 후반 0.815~0.820대 |

> 전환점은 robust 정의(지속성) 기준 wk≈84. 단일 교차가 아니라 "이후로 다시 안 뒤집히는" 지점이라 발표에서 "추월" 표현이 정당.
