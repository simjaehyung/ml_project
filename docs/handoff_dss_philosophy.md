# 핸드오프 — DSS "정제 레이어" 철학 구현 프롬프트 (코드방용)

> 용도: 코드 작업방에 아래 프롬프트를 그대로 붙여 에이전트를 띄운다.
> 목적: 기존 앱을 새 철학("AI-ready 다기준 정제 레이어")이 **UI에 새겨지도록** 수정 — 도메인을 1급 criteria card로.
> 작성: 전체흐름방 2026-06-07. v1(전문가 패널 결과 반영 전; 핵심은 불변). 발표 6/10·3일 남음.

## 붙여넣을 프롬프트

```
너는 Hotel No-Show DSS의 시니어 풀스택 + ML 엔지니어다. 단일 임무 — 기존 앱을 수정해 **하나의 철학을 UI에 새긴다**: "DSS = AI가 바로 판단할 수 있게 정제된, 다기준 데이터 레이어." 도메인을 '1급 criteria card'로 승격하고, 정직한 실시간-정리 / 배치-학습 경계를 지킨다.

[철학 — 모든 결정의 기준]
AI 시대엔 raw 데이터를 그냥 AI에 던지면 좋은 분석이 안 나온다(기본 프롬프트로는 머신러닝이 자동으로 안 돈다). AI가 전문가처럼 판단하려면 '검증된 다기준 분석 도메인으로 미리 정제된 데이터'가 필요하다. DSS는 예약이 들어오는 '즉시' 판단 기준별 도메인(오버부킹·업셀·동적가격·수요/인력)으로 정리해, 그 위의 AI/모델이 raw를 씹는 것보다 훨씬 나은 기준으로 판단하게 만든다. 메커니즘 = 검증된 ML 채점(LightGBM 0.820) + 다기준 도메인 구조화. 포지션 = AI 대체가 아니라 force-multiplier(어떤 AI든 우리 레이어 위에선 더 잘 판단).

[현재 앱 상태 — 먼저 Glob/Read로 확인]
- hotel-dss-app(Next.js) + api(FastAPI:8001). 허브는 백엔드 없이 단독 구동.
- New Booking(`app/dashboard/reservations/new/`): 토글 [신규 입력] [자동 유입 데모(auto-feed-demo.tsx)] [도메인 인박스(domain-inbox.tsx)]. auto-feed가 캐글 `public/hub_stream.json`(25k 시간순)을 재생하며 4도메인으로 실시간 라우팅.
- Hub(`/dashboard/hub`): 성장곡선 0.387→0.820 (사전계산 재생, hub_stream.json/hub_growth.json).
- 4도메인(현 라우팅 규칙): D1 오버부킹=실모델(risk≥0.5) / D2 업셀=규칙(ADR≥€110) / D3 동적가격=규칙(lead≥90일) / D4 수요·인력=규칙(성수기 도착).

[만들/고칠 것 — 철학을 UI에 새긴다]
1) ★도메인 = "criteria card" 1급 시민화. auto-feed/domain-inbox의 도메인 패널을 정식 '기준 카드'로 승격. 각 카드 구성:
   - [도메인명 + 성숙도 배지: 실모델 / 규칙 / 설계]
   - 입력 신호(이 도메인이 소비하는 필드)
   - 판단 기준(규칙 또는 모델의 결정 로직)
   - 권장 출력(이 도메인이 내는 권고)
   - 실시간 라우팅 수(스트림에서 이 도메인으로 정리된 건수)
   - 'AI-ready' 표시: raw가 아니라 '정제된 기준'으로 제공된다는 한 줄/배지
   카드 내용(정전 — 지어내지 말 것):
   · D1 오버부킹 — 입력: 취소위험·lead_time / 기준: 뉴스벤더(한 명 더 받는 이득=손해 지점) / 권장: 세그먼트 8~30% / 성숙도: 실모델(LightGBM 0.820)
   · D2 업셀·식음 — 입력: ADR·세그먼트 / 기준: ADR≥€110 / 권장: 업셀·식음 타겟 / 성숙도: 규칙
   · D3 동적가격 — 입력: lead_time·수요 / 기준: lead≥90일 / 권장: 가격 조정 / 성숙도: 규칙(설계)
   · D4 수요·인력 — 입력: 계절·점유 / 기준: 성수기 도착 / 권장: 인력 배치 / 성숙도: 설계
2) Domains 개요 뷰(권장 신규 `/dashboard/domains`, 또는 기존 뷰 승격). 4 criteria card를 한 화면에. 상단 타이틀: "raw가 아니라 '판단 기준'으로 정리된 컨텍스트 — 어떤 AI든 더 잘 판단." 라우팅이 실시간으로 채워지는 모습.
3) "AI가 소비" 가시화. 정제된 도메인을 AI/모델이 읽는다는 걸 한 요소로(카드의 'AI-readable' 배지, 또는 "이 기준을 AI에 넘기면 →" 흐름). 과장 금지.
4) (선택·여유 시) 사이드바 nav에 'Domains' 1급 항목. 단 허브 캡처 일관성 위해 기존 좌측 nav를 함부로 바꾸지 말 것(추가만).

[정직 경계 — 하드 룰]
- '정리(라우팅·피처화)' = 실시간 OK(auto-feed가 실제로 함). '모델 학습' = 배치(월 1회). 데모 성장곡선 = 사전계산 재생. 이 셋을 섞어 말하지 말고 라벨로 구분.
- 도메인 성숙도 정직히 표기(D1만 실모델, D2~D4 규칙/설계). "전부 AI가 돌린다" 식 과장 금지.
- 수치 날조 금지(정전값만). RevPAR 등 미검증값은 헤드라인 금지.

[범위 규율 — 3일]
- 새로 짓기보다 기존 auto-feed/domain-inbox/hub를 '승격·정제'. demo-stable(허브처럼 백엔드 없이 도는 경로 유지). 데이터는 hub_stream.json 필드 재사용(risk/adr/lead/arr/country/channel/hotel/canceled/color).
- PMS·OTA·결제·실제 재학습 파이프라인은 범위 밖.

[정전 수치 — 그대로]
PR-AUC 0.820(=LightGBM 0.8189) · Dummy 0.387 · 2.1배 · 오버부킹 세그먼트 8~30%(≤7일 8% … >180일 30%) · 보상 리스본 €120~420(등급·계절) · 취소율 37%.

[완료 정의(Definition of Done)]
- 도메인이 criteria card로 1급 표현(입력·기준·권장·성숙도·AI-ready). Domains 개요 뷰 동작.
- 정직 라벨(실시간 정리 / 배치 학습 / 사전계산 재생) 명시.
- tsc 0 · build 0 · 헤드리스 스모크(라우팅 채워짐·카드 렌더·에러 0). 1920×1080 캡처 1~2컷을 `presentations/captures/`에.
- 짧은 보고: 무엇을 승격/추가했나 · 무엇이 실시간 vs 배치 vs 사전계산인가 · 데모 동선 한 줄.

먼저 Glob/Read로 현재 구조(특히 auto-feed-demo.tsx·domain-inbox.tsx·hub)를 파악하고, 1) criteria card 승격부터 실제로 구현·검증하라. 돌려보고 말해라.
```

## 코드방 전달 메모
- 발표 핵심 동선과 일치: **New Booking 자동유입 → 도메인(criteria card) 즉시 정리 → Hub 모델 성장.** 덱 S3도 이 프레이밍으로 갱신됨.
- 캡처가 `presentations/captures/`에 오면 전체흐름방이 덱 S3/S12 슬롯에 꽂는다.
- 정직 경계가 발표 방어의 핵심: 정리=실시간 / 학습=배치 / 데모=사전계산 재생.
- ※ v1. 아래 v2(전문가 패널 반영)로 우선순위·범위가 보강됨 — v1 핵심(criteria card·정직 경계·범위)은 불변.

## v2 — 전문가 패널 반영 (5인 + 종합, 2026-06-07)

**패널 합의:** 도메인을 1급으로 보이게 · 0.820=증거 앵커(격하 금지)+calibration/드리프트 연결 · "정리=실시간 / 재학습=배치" 경계 1회 명확 선언 · LLM €46은 "씨앗"이 아니라 Phase 2 계획으로 명시 · 슬라이드는 기능 완성, 남은 3일은 메시지·정직함·리허설.

**★ 코드방 우선순위 (3일 범위 — 앱 대수술 금지, demo-stable 우선):**
1. (~1h) New Booking 토글 → **Domain Selector**로 도메인이 더 잘 보이게(라벨·노출 강화). 도메인 전용 새 페이지 대수술은 Phase 2로 유예.
2. (~1h) 대시보드에 **"마지막 재학습 일자(Last Retrain)" 타임스탬프** + 신선도 표시 — *정리=실시간 / 모델 채점=정적 / 재학습=월 1회 배치*. (패널 만장일치: 이 경계가 신뢰의 핵심)
3. (~2h) 도메인 패널 → **criteria card**(입력신호·판단기준·권장·성숙도·AI-ready). **D1은 풀**(SHAP·PR-AUC 0.820), **D2~D4는 규칙 + 성숙도 배지**(실모델/규칙/설계 — 과약속 금지).
4. demo-stable · 정직 라벨 · 정전 수치 보존. 도메인 카드 영속화·전용 대시보드는 Phase 2.

**가장 강한 thesis(패널 채택):** "호텔 매니저가 복잡한 거래를 한 번에 구조화된 데이터로 판단하게 만들었고, 그 판단이 매월 자동으로 정확해진다 — 이것이 LLM 시대 우리의 경쟁력."

**코드방 아님(팀/발표):** 6/9 전체 리허설 1회 필수 · Q&A 시나리오 3~5개("왜 LLM 파인튜닝 안 했나"·"3일에 뭐가 진짜 되나"·"정리는 실시간인데 모델은 월 1회?") · S3에서 "사전계산 재생" 구두 정직선언.
