## 1조 — MAS Lens: 논문 인용 수 예측 및 Matthew Effect 정량화

### 내용 요약

동일한 모델에서 저자 명성 피처(h-index, 컨퍼런스 티어 등)를 넣었을 때와 뺐을 때의 R² 차이(ΔR²)로 Matthew Effect를 정량화한 프로젝트다. Semantic Scholar API로 수집한 2020년 출판 CS 논문 64만 편을 사용했으며, 1,550회 이상 인용 기준으로 필터링했다. CS 단일 분야를 선택한 이유는 분야마다 인용 문화가 달라 명성 효과와 분야 효과가 섞이기 때문이고, 2020년 단일 연도를 쓴 이유는 2025년 수집 시점에서 정확히 5년 치 인용이 쌓여 모든 논문의 인용 기회가 동등하기 때문이다.

피처는 텍스트(TF-IDF, 향후 SciBERT 예정)와 명성 피처 6개(h-index 최대·평균, 최고 저자 h-index, 공저자 수, 출판 저널 등급, 참고 문헌 수)로 구성했다. 실험 A(원문 초록)와 실험 B(저자명·기관명 마스킹 초록)를 비교해 텍스트 내 간접 명성 단서의 영향을 분리했다. 모델은 XGBoost, 타깃은 로그 변환 인용 수(중앙값 5, 최대 1만 이상의 극단 편향으로 변환 필수).

주요 결과: 모델 B(텍스트만) R²=0.266, 모델 A(텍스트+명성) R²=0.471, **ΔR²=0.205** (95% CI: 0.201~0.209, 부트스트랩 1,000회). 실험 A와 B의 ΔR² 차이는 0.0003으로 사실상 동일 → 명성 효과는 초록 내 간접 단서가 아닌 h-index·컨퍼런스 티어 같은 명시적 피처에서만 작동함을 확인했다. 서비스로 패키징하여 초록 입력 시 예측 인용 퍼센타일, SHAP 하이라이트, Matthew Effect 시각화를 제공할 계획이다.

### 교수님 코멘트 요약

- **단일 변수 기준선 필요:** 변수를 하나 추가하면 R²는 기계적으로 증가한다. 명성 피처가 단독으로 얼마를 설명하는지, 텍스트 모델 자체의 설명력이 거의 없는 상태에서 명성 피처가 방향성을 준 것은 아닌지를 먼저 확인해야 한다.
- **"명성 피처만 넣은 모델 vs 텍스트만 넣은 모델" 비교를 선제 제시해야** ΔR² 해석이 견고해진다. 현재처럼 A-B 비교만으로는 "명성이 설명력을 추가한다"는 주장의 근거가 약하다.
- 수치의 의미를 발표자 스스로 해석할 수 있어야 한다. 교수님 코멘트를 듣고 끝내는 것이 아니라, 그 코멘트를 스스로 먼저 예상하고 답할 수 있어야 한다.

### 감상평

ΔR² 프레임워크 자체는 인과 추론 방식과 유사한 접근으로 설득력이 있다. 그러나 교수님 지적대로 기저 모델(텍스트만)의 설명력이 낮은 상태에서 명성 피처가 "차이"를 만든 것인지, 아니면 명성 피처 하나가 거의 전체 예측력을 담당하는 것인지를 먼저 분리했어야 한다. 마스킹 실험의 발상은 창의적이고 결과 해석도 명확했지만, "명성 피처 단독 모델" 하나가 없어서 논리의 중간 단계가 빠진 느낌이다. h-index의 시점 문제(2025년 값을 2020년 데이터에 소급 적용)를 한계로 직접 인정한 점은 발표 신뢰도를 높였다. SciBERT 실험과 분야별 Matthew Effect 차이 분석까지 완성되면 충분히 논문 수준의 기여가 될 것 같다.

## 2조 — 호텔 예약 취소 기반 오버부킹 의사결정 지원 시스템

### 내용 요약

호텔의 오버부킹 전략을 데이터 기반으로 최적화하는 DSS를 설계했다. 오버부킹은 취소를 예상하고 초과 예약을 받는 전략으로, 예측이 맞으면 수익 극대화, 틀리면 walk(초과 투숙 손님 강제 퇴실) 보상 비용이 발생한다.

머신러닝 모델로 개별 예약의 취소 확률을 예측하고 임계값 초과 예약을 Flexi 풀(취소 가능형 상품)로 라우팅하는 구조다. Flexi 풀 등록 시 할인율은 `5% + (위험점수 - 0.5) × 26%`로 자동 산출한다. 앱은 세 가지 탭으로 구성된다: (1) 기존 예약 위험 리스트 + SHAP 위험 근거 3가지, (2) 신규 예약 입력 → Flexi 라우팅 권장, (3) 오늘 신규 예약 관리 + 최적 Flexi 등록 수량 자동 추천.

LLM 기반 협상 시스템은 walk 발생 시 고객에게 제시할 최적 보상 오퍼를 생성한다. ABM(에이전트 기반 시뮬레이션)은 감정·상황 변화 반영이 어려워 LLM을 선택했다. 고객 유형별(B타입 레저 커플, D타입 가격 민감형 등) 실험에서 심리적 앵커 포인트가 다르게 나타났다: B타입은 약 91유로, D타입은 약 46유로 근처에서 수락률이 급변했다. 협상 로그가 누적되면 LLM 협상 → 호텔 맞춤형 ML 시스템으로 진화하는 데이터 플라이휠 구조가 장기 목표다.

### 교수님 코멘트 요약

- **기존 Kaggle 솔루션과의 차별점**을 명확히 해야 한다. 호텔 예약 취소 예측 자체는 이미 많이 올라온 주제다. 이 팀의 차별점은 LLM 기반 협상 모듈이라는 점을 발표 초반에 위치시켜야 한다.
- **법적 리스크 검토 필수:** 한국은 고객 우선주의 문화가 강하고, 오버부킹 손님이 보상금을 목적으로 끝까지 클레임을 거는 진상 고객 케이스가 실제로 있다. 호텔이 이 시스템을 도입했을 때 법적으로 방어 가능한 근거(오버부킹 정책, 보상 기준 법령)를 함께 제시해야 현장에서 실제로 쓸 수 있다. 법적 단서가 없으면 호텔이 사용하지 않는다.

### 감상평

우리 조 발표다. 발표 흐름은 오버부킹 리스크/리턴 → ML 예측 → Flexi 라우팅 → LLM 협상 → 데이터 플라이휠 순으로 자연스럽게 이어졌다고 생각하지만, 교수님 지적을 들으며 법적 리스크를 빠뜨렸다는 점을 실감했다. LLM 협상을 써서 고객 심리 앵커를 실험으로 측정한 것은 차별점이 맞지만, "이 시스템이 실제 호텔에서 법적으로 운영 가능한가"가 선행되지 않으면 기술 데모로만 머문다. 최종 발표에서는 한국 숙박업 오버부킹 관련 법령(약관 공시 의무, 보상 기준 등)을 조사해서 "이 시스템이 어떤 조건에서 안전하게 운영 가능한지"를 명시할 필요가 있다. 할인율 공식과 LLM 협상 결과는 흥미롭고 구체적이었다.

## 3조 — 한국 국고채 3년물 금리 일별 변화량 예측

### 내용 요약

일별 금리 변화량(수준이 아닌 변화량)을 타깃으로 삼고, 분위수 회귀(핀볼 로스)로 q05/q50/q95 세 분위를 동시에 예측해 90% 예측 구간을 제공하는 프로젝트다.

22개 거시경제 후보 변수에서 3단계 필터링(상관 |r|≥0.05, VIF<12, p<0.05 그랜저 검정)을 거쳐 8개 최종 변수를 선택했다. 데이터는 train(2010~2020), calibration(2021), validation(2022), test(2023~2025) 4구간으로 분할했다. 8개 변수를 lag·rolling 통계로 108개 피처로 확장하고, 스케일링은 미래 정보 유입 차단을 위해 expanding window 통계만 사용했다.

베이스라인: Naive 50%, ARIMA 최적 조합 52.7%(35가지 조합 전수 검색) → 단변량 시계열만으로는 예측 불가임을 입증, XGBoost/LSTM의 필요성 확인. 핵심 발견: 미국 변수 데이터 누수 — 한국 채권 시장은 15:30 마감이나 유럽·미국 종가는 다음 날 새벽 5:30 형성, 동일 날짜로 기록되나 실질적으로 14시간 미래 정보. shift-1 적용 후 LSTM 방향 정확도 65.2% → 49.8%로 하락. 이후 도메인 파생 변수 5개(한미 금리 차, 미국 금리 변화량, VIX 변화량, 달러 변화량, 위기 더미) 추가 후 XGBoost v2 방향 정확도 61%(3-fold 평균), p<0.001로 Naive 대비 통계적 유의. CQR(Conformal Quantile Regression) 보정 시 커버리지 85.3% → 98.4%이나 구간 폭 11.6bp → 24.8bp로 2배 확대, 실용성 트레이드오프 확인.

### 교수님 코멘트 요약

- **VIF 높다고 무조건 제거하면 안 된다.** 다중공선성이 높은 두 변수 중 하나가 먼저 모델에 들어가면 SHAP·중요도를 독점하고 나머지가 무의미해 보이는 착시가 생긴다. 이는 제거 근거가 아니라 "해석에 주의하라"는 경고 신호다.
- 변수 선택 전략은 **"예측"이 목적인지 "해석"이 목적인지에 따라 달라진다.** 예측 목적이면 공선성 있는 변수를 둘 다 넣어도 무방하나, 해석 목적이면 도메인 지식으로 그루핑 후 대표 변수 1개를 신중히 선택해야 한다.
- 빼버리고 남은 변수가 "진짜 중요한 것"이 아니라 "두 변수 중 살아남은 것"일 수 있다는 점을 항상 고려해야 한다.

### 감상평

데이터 누수를 직접 발견하고 수정한 과정이 이 발표의 가장 큰 강점이다. 65.2% → 49.8% 하락을 숨기지 않고 그대로 발표에 포함한 태도가 신뢰감을 줬다. 분위수 회귀로 점 추정 대신 90% 예측 구간을 제공하는 접근도 실무 친화적인 설계다. 다만 변수 선택에서 VIF 기준을 기계적으로 적용한 것은 교수님 지적처럼 한계가 있고, 특히 한미 금리 차 같은 파생 변수를 도메인 지식으로 추가하는 방향은 옳지만 "왜 이 5개인가"의 설명이 부족했다. CQR 보정 후 구간이 24.8bp로 넓어지는 트레이드오프를 인정한 점도 솔직했지만, 발표 청중 입장에서 "그래서 이 시스템을 쓰면 뭐가 좋은가"에 대한 마무리 메시지가 더 강해야 할 것 같다.

## 4조 — 한국 상장기업 파산 예측 기반 대출 심사 DSS

### 내용 요약

기존 대출 심사 시스템의 한계(단일 시점 재무 비율, 시계열 추세 무시, 연쇄 부실 전이 미반영, 블랙박스)를 해결하는 CNN-LSTM 기반 조기 부실 탐지 시스템이다.

데이터: DART API로 3,962개사 14년치 재무제표, 네이버 뉴스 8만 건(감성 분석), 업종·재무유사도·규모 기준 64,000개 엣지 관계망. 피처 28개(재무비율 19개, 뉴스 감성 5개, 관계형 4개)와 연도별 변화율 파생 변수로 시계열 신호를 강화했다. 클래스 불균형 40:1은 CTGAN으로 파산 74건 → 4,514건 증강(4:1로 완화), Focal Loss(α=0.75, γ=2.0) 적용. 테스트셋은 원본 40:1 비율 유지. 기업 단위 8:2 분할로 동일 기업 연도 데이터의 train/test 혼입을 차단했다.

성능 진화: Altman Z-Score PR-AUC 0.27 → LR 0.61 → LightGBM 0.64 → CNN-LSTM **0.79**, 재현율 74%. CNN과 LSTM을 결합한 이유는 CNN이 2~3년 중기 패턴과 SE 블록 채널 어텐션으로 지표별 중요도를 자동 학습하고, LSTM이 장기 의존성을 처리하기 때문이다. 핵심 발견: 뉴스 피처 데이터 누수 — 연도별 분리 없이 전기간 합산 뉴스 데이터를 사용해 미래 부정 뉴스가 과거 시점 데이터에 유입됨. Permutation Importance 1위가 뉴스 카운트(30~42%). 최종 발표 전 연도별 수집으로 재처리 예정.

DSS 활용: PD 값 기준 대출 승인 여부, 적정 금리(기준 3.5% + 구간별 1.5~5% 가산), 대출 한도(영업현금흐름+담보 70%), 예상 손실(PD × LGD × 잔액) 자동 산출.

### 교수님 코멘트 요약

- **뉴스 누수 발견은 잘 했다.** 모델 선정 후에 발견했지만 직접 공개하고 수정 계획을 명시한 점이 좋다.
- 최종 발표에서는 **"기존 연구의 한계가 무엇이고, 우리가 무엇을 추가했으며, 그로 인해 성능이 얼마나 달라졌는지"**가 한 흐름으로 연결되어야 한다. 선행 연구 소개와 모델 결과가 따로 놀지 않아야 한다.
- CNN-LSTM 조합의 이론적 근거, 기업 관계망 유사도 측정 방식에 대한 선행 연구 보강이 필요하다.

### 감상평

파산 예측처럼 극단적 클래스 불균형과 시계열 특성이 공존하는 문제를 다층으로 접근한 설계가 인상적이었다. CTGAN으로 합성 데이터를 생성하면서도 테스트셋은 원본 40:1 비율을 유지한 것은 올바른 판단이다. 뉴스 누수를 발표에서 직접 공개한 용기도 평가할 만하다 — 감추는 것보다 "발견하고 수정하겠다"가 훨씬 설득력이 있다. 다만 CNN-LSTM을 선택한 근거가 "성능이 가장 좋았기 때문"에 머물렀는데, "왜 CNN이 재무 시계열의 중기 패턴을 포착하는가"를 이론적으로 설명했다면 더 강한 발표가 됐을 것이다. 관계망 그래프 데이터의 활용도 흥미롭지만, 현재 발표에서는 관계망이 모델 성능에 실질적으로 기여한 수치가 빠져 있었다.

## 5조 — 머신러닝 기반 퀀트 펀드 의사결정 지원 시스템

### 내용 요약

주가 절대 수준이 아닌 "코스피 200 대비 5거래일 초과수익 여부"를 이진 분류 타깃으로 설정한 퀀트 DSS다. 초과수익 종목을 찾는 것이 목적이므로 시장 전체 상승 시에도 상대적으로 강한 종목만 추출한다.

데이터: 코스피 200 유동성 상위 50종목의 OHLCV, 코스피 200 지수, 업종 지수, 원달러 환율·금리(거시), 거래 캘린더. 피처는 종목 모멘텀(5일/21일 수익률), 이동평균 대비 위치(MA5/MA21 괴리율), 코스피 200 대비 초과수익(5일), 업종 내 상대 강도 등 종목·시장·업종·거시를 통합 설계했다.

3단계 실험: ① 분류 성능 비교(50종목, 랜덤 포레스트 밸리데이션 ROC-AUC 0.5303, Precision 0.523), ② 탑5 포트폴리오 백테스트(일부 ML 모델이 단순 모멘텀 대비 높은 누적 수익률), ③ 워크 포워드 + 거시 오버레이 대시보드(서비스 확장성 검토). 2026-05-20 기준 실시간 예측 탑5: 두산로보틱스, 한화오션, LG전자, 삼성물산, 한화에어로스페이스(3거래일 경과 시점 기준 3개 상승 / 2개 하락, 단순 평균 등락률 1.7%).

한계 인정: 실험별 유니버스·조건 불일치, 2026년 초 성과 악화 구간, 거래 비용·슬리피지 미반영.

### 교수님 코멘트 요약

- **변수 선택 근거 보강 필요:** 피처를 어떤 기준으로 선정했는지 도메인 지식과 EDA 결과의 연결이 발표에서 명확하지 않았다.
- 발표 분량이 길어지자 교수님이 중간에 "넘어가자"고 요청 — 핵심 메시지를 앞에 배치하고 부수 내용을 뒤로 빼는 발표 구조 개선이 필요하다.

### 감상평

"절대 수익이 아닌 시장 대비 초과수익"을 타깃으로 삼은 문제 정의가 실무 관점에서 가장 현실적인 설정이라고 느꼈다. 단순히 모델 성능(ROC-AUC)만 보지 않고 탑5 포트폴리오 백테스트와 워크 포워드를 병행해 "이 모델이 실제 투자 전략으로 의미 있는가"를 여러 각도에서 검증하려 한 구조도 인상적이었다. 그러나 ROC-AUC 0.53이라는 수치가 갖는 의미 — 무작위보다 약간 높을 뿐이라는 것 — 를 발표자가 직접 충분히 해석하지 않았다. 분류 성능이 낮음에도 백테스트 수익률이 나오는 이유를 설명했다면 훨씬 설득력 있었을 것이다. 2026년 초 성과 악화 구간의 원인 분석(시장 국면 변화?)을 최종 발표에서 추가하면 완성도가 높아질 것 같다.

## 6조 — 진로 목표 기반 전공 강의 추천 RAG 챗봇

### 내용 요약

희망 진로를 입력하면 학과 과목 중 관련성이 높은 과목과 추천 이유를 제공하는 RAG 챗봇이다. 수강 편람에는 직업과 과목의 연결이 직접적으로 제공되지 않아 학생이 진로 연계 수강 신청을 하기 어렵다는 문제를 해결한다.

저장 구조는 이중 스토리지로 설계됐다. SQLite는 과목명·학점·개설 여부 같은 정형 데이터를 담고, ChromaDB는 과목 설명 임베딩을 저장해 의미 기반 검색에 사용한다. 추천 흐름은 진로 선택 → 직업별 키워드 추출 → 임베딩 검색 → SQLite에서 실제 개설 여부 필터링 → 로컬 LLM이 과목 정보를 근거로 추천 이유 생성 순이다. API 키 없이 독립 실행이 가능하고 수강 편람 데이터를 외부 서버로 전송하지 않는다는 점에서 로컬 LLM을 선택했다.

직업별 키워드는 현재 수작업으로 정의했는데, 이 주관성 문제를 해결하기 위해 채용 공고에서 자주 등장하는 직무 역량 단어를 추출해 키워드 기준으로 삼을 계획이다. 데모 모드(키워드 매칭)와 API 모드(임베딩 유사도 검색)를 분리 운영하며, LLM이 수강 편람에 없는 내용을 추측하지 않도록 검색된 과목 정보만을 근거로 답변을 생성하도록 설계한다.

### 교수님 코멘트 요약

- **고정 직업 카테고리 대신 유사도 측정으로 전환 필요:** 사용자가 아무 직업이나 자유 입력할 수 있는데, 미리 정해진 카테고리 밖의 키워드는 처리가 안 된다. 직업 카테고리 매칭이 아닌 입력 키워드와 과목 임베딩 간의 유사도를 직접 측정하는 방식이어야 한다.
- **3·4학년 과목으로 제한하지 말고 전체 학년으로 확장 권장:** 미적분·일반물리 같은 순수 기초만 제외하면 1·2학년 과목도 진로 관련성이 있을 수 있다.

### 감상평

RAG 구조가 "LLM이 없는 정보를 지어내지 않도록 한다"는 목적에 명확하게 연결된 점이 인상적이었다. 로컬 LLM 선택 이유(비용, 데이터 외부 전송 방지)도 실용적인 판단이다. 다만 추천 품질의 핵심이 되는 직업-키워드 매핑이 현재 수작업 기반이라는 점이 취약점이다. 채용 공고 기반 키워드 추출로 보완할 계획은 있지만, 추출된 키워드가 우리 학과 과목과 얼마나 겹치는지 — 즉 "추천 가능한 과목이 존재하는가"를 미리 확인하는 단계가 없으면 시스템 자체가 "관련 과목 없음"만 출력할 위험이 있다. 교수님 지적대로 학년 제한 해제와 유사도 직접 측정으로 전환하면 범용성이 크게 높아질 것 같다.

## 7조 — 호텔 예약 취소 기반 오버부킹 최적화 DSS

### 내용 요약

2조와 동일한 호텔 예약 취소 예측 주제지만, 접근 방향이 다르다. 이 팀은 "개별 예약 위험 분류"가 아닌 **"오늘 몇 개 객실을 추가로 판매해야 하는가"는 단일 행동 지침 도출**에 집중했다. SHAP은 목적이 아니라 수단이며, 최종 output은 대시보드에 표시되는 구체적인 오버부킹 수량 추천이다.

XGBoost 모델: ROC-AUC 0.9458, F1 0.8145, Brier Score 0.099. 시간 분할(train/val/test 3구간)을 사용했고 세 구간 모두 취소율 37% 수준으로 안정적이었다. 핵심 단계는 **확률 보정(캘리브레이션)**: XGBoost의 출력값은 확률이 아닌 점수이므로 Isotonic Regression으로 보정했고, ECE가 0.0477에서 0.0078로 6.1배 개선됐다. 보정된 확률을 기반으로 기대수익을 계산한다: `기대수익 = ADR × (1 - p_cancel) - 보상비용 × p_arrive`. SHAP 분석 결과 주차 요청(parking request)은 취소 가능성을 낮추는 신호, deposit_type은 취소율이 높다는 신호로 나타났다.

민감도 분석: ADR 10만~25만원 × 보상배수 1.0~2.0을 그리드로 탐색했을 때 최적 오버부킹 수량 변화폭이 1.5%에 불과해 파라미터에 강건함을 확인했다. 대시보드에는 "오늘 23개 객실 추가 판매 권장"처럼 직관적인 행동 지침이 표시된다. 향후 생존 분석 도입으로 체크인 D-60/30/7 시점별 동적 오버부킹 재조정 계획.

### 교수님 코멘트 요약

- **악의적 사용 케이스 고려 필수:** 오버부킹 보상금을 노리고 의도적으로 클레임을 거는 진상 고객 케이스가 실제로 있다. 한국 숙박업 맥락에서 이 시스템이 법적으로 방어 가능한지, 호텔이 책임을 지게 되는 조건이 무엇인지를 명시해야 한다.
- 시스템에 **조건/단서를 달아야** 현장에서 실제로 사용할 수 있다. "이런 경우에는 이 시스템을 쓰면 안 된다"는 사용 제약 조건이 있어야 호텔이 안심하고 도입할 수 있다.

### 감상평

확률 보정 단계를 명시적으로 포함한 것이 이 팀의 가장 큰 강점이다. 대부분의 호텔 취소 예측 프로젝트가 ROC-AUC에서 끝나는 반면, 이 팀은 "보정된 확률이 실제 확률에 가까워야 기대수익 계산이 의미 있다"는 논리를 끝까지 일관되게 유지했다. 민감도 분석으로 파라미터 선택이 결과에 크게 영향을 주지 않음을 보인 것도 발표 신뢰도를 높였다. 그러나 교수님 지적처럼 악의적 사용자 케이스와 법적 근거가 빠져 있으면 "기술적으로 완성됐지만 현장에서 쓸 수 없는 시스템"이 된다. 2조와 비교하면 7조는 오버부킹 수량이라는 단일 output에 집중해 명확하고, 2조는 개별 예약 위험과 SHAP 근거 제공에 집중해 설명 가능성이 높다는 점에서 상호 보완적인 접근이었다.

## 8조 — 서울시 따릉이 수요 예측 및 운영 최적화

### 내용 요약

시간대·날씨·요일·대여소 특성에 따른 따릉이 수요를 머신러닝으로 예측해 재배치 전략에 활용하는 프로젝트다. 출퇴근 시간대 급증, 새벽 극소, 금요일 최고 수요 등 비선형 패턴이 주요 예측 과제다.

핵심 피처는 대여소별 시간대·요일 평균 수요(입지 특성 대리변수)다. Lag 피처(1시간/24시간/7일 전 실수요)와 기상 정보(기온, 강수량, 습도), 출퇴근·공휴일 변수도 포함한다. 파생 변수 Demand Ratio는 대여소 규모 효과를 제거하고 순수 시간대 패턴만 표준화해 대여소별 고유 패턴을 반영한다. 시간 순환 인코딩(sin/cos)으로 23시-00시, 12월-1월 연속성을 보장했다. 새벽(00~05시)은 극단적으로 적은 대여 건수가 MAPE를 왜곡하므로 주간과 분리 학습했다. 검증은 Walk-Forward 4-fold로 사계절 전체를 학습하도록 설계했다. 모델: 단기(LightGBM + XGBoost 앙상블), 장기(ExtraTree).

### 교수님 코멘트 요약

- **근본적 문제:** 이동 전후 데이터가 없으면 "진짜 수요 부족"(빈 대여소에 오려다 실패한 건수)을 알 수 없다. 현재 모델은 이미 일어난 대여 수를 예측하는 것이지, 충족되지 못한 수요를 예측하는 것이 아니다.
- 제목을 "현재 수요량 예측"으로 수정하는 것이 더 정확하며, 실제 재배치 효과 검증(이동 전후 비교)이 없으면 "최적화" 주장이 성립하지 않는다.

### 감상평

Demand Ratio 파생 변수와 dawn/daytime 분리 학습처럼 도메인 지식을 피처 설계에 녹인 부분들이 탄탄했다. 그러나 교수님 지적이 정확하다 — "재배치 최적화"라는 제목과 실제 모델이 하는 일(관측된 대여 수 예측) 사이에 논리적 점프가 있다. 자전거가 이미 배치되어 있어서 그만큼 대여된 것인지, 아니면 수요가 있어서 대여된 것인지를 구분하는 데이터 없이는 재배치 효과를 주장하기 어렵다. 이 한계를 발표자가 먼저 인지하고 "수요 예측 모델로서의 가치"를 전면에 세운 뒤 재배치는 응용 가능성으로만 언급했다면 더 견고한 발표가 됐을 것이다.

## 9조 — 음료 제조 공정 스마트 품질 관리 DSS

### 내용 요약

병 투입→캡 체결→라벨→패키지→출하 검사 5단계 음료 제조 공정에서 불량 탐지·장비 이상 탐지·유지보수 의사결정을 통합한 시스템이다. 중간 검사 도입 여부(비용 vs 불량 감지 효과)를 시나리오 비교로 정량화하는 것이 핵심이다.

구성 요소: ① 이미지 결함 탐지 — Random Forest (RGB·색상 히스토그램 피처), ② 설비 이상 탐지 — Random Forest (온도·회전속도·토크·공급압 파생 변수), ③ 장비 상태 전이 — Markov Process (정상→위험→고장, Stationary 가정), ④ 잔여 수명 예측 — Random Forest (실제 유지보수 데이터 기반). 실제 라인을 멈춰 실험할 수 없으므로 시뮬레이션으로 4가지 시나리오를 비교했다: 중간 검사 유무 × 문제 공정 부분 정지 vs 전체 라인 정지. 결과: 문제 공정만 부분 정지하는 전략이 전체 라인 정지 대비 2배 이상 비용 효율이 높았다.

### 교수님 코멘트 요약

- **두 효과가 혼재:** 장비 수명 감소로 인한 불량률 증가 경로와 불량 탐지 자체의 효과가 섞여 있다. 장비 상태가 정상인데 불량이 발생하거나 그 반대인 "미스매치" 케이스를 기반으로 한 의사결정이 보완돼야 한다.
- 발표에서 이 시스템의 핵심 목적이 **"비용 절감"**임을 처음부터 명확히 위치시켜야 한다.

### 감상평

공정 시뮬레이션으로 "A안 vs B안 × 비용 기준" 비교를 수치로 보여준 구조가 의사결정 지원 시스템의 포맷에 잘 맞았다. Markov Process로 상태 전이를 모델링한 아이디어도 인상적이었다. 다만 교수님 지적처럼 "장비 이상이 불량을 유발하는 경로"와 "불량 탐지 모델의 경보"가 일치하지 않는 케이스가 실제 공장에서 가장 까다로운 상황인데, 현재 설계는 이 두 경로가 정렬된다고 암묵적으로 가정하고 있다. 미스매치 케이스에서 어떤 판단을 내려야 하는지가 의사결정 시스템의 진짜 가치가 되는 지점이므로, 이 부분을 최종 발표에서 명시적으로 다루면 완성도가 높아질 것이다.

## 10조 — 이메일 마케팅 업리프트 모델 (T-Learner)

### 내용 요약

할인 이메일을 받으면 실제로 행동이 바뀌는 고객(Persuadables, 9.6%)만 골라내는 업리프트 모델을 구축한 프로젝트다. Hillstrom Email Marketing 실험 데이터(64,000명, 3그룹 RCT)를 사용했다.

고객 유형 4종: Persuadables(이메일 덕분에 구매), Sure Things(어차피 구매), Lost Causes(이메일 무관 미구매), Sleeping Dogs(이메일에 역효과). 기존 Response Model은 "어차피 살 사람"과 "이메일 덕분에 사는 사람"을 구분하지 못하는 한계가 있다. S-Learner(보수적), X-Learner(86% 효과 있음 — 과적합 의심), T-Learner(21%, 균형)를 비교해 T-Learner를 최종 선택했다. T-Learner는 발송/미발송 그룹을 별도 모델로 학습해 업리프트 분포가 가장 신뢰할 수 있다.

수익 계산: 이메일 발송 그룹 매출 - 대조군 매출 기준선, 마진 30% 적용, 발송비용 $0.05/건 차감. 결과: 상위 15% 타겟팅 시 발송량 85% 감소, 순이익 82% 증가, ROI 43.8배.

### 교수님 코멘트 요약

- **Sure Things의 이메일 비용은 줄이지만, 그 이상의 가치가 있는가:** 어차피 살 사람에게 이메일을 안 보내도 되니 비용이 절감된다는 논리는 맞지만, 이메일이 충성도나 재구매율을 높이는 효과가 있다면 Sure Things에게도 보내는 것이 나을 수 있다. 이 부분이 분석에 빠져 있다.
- 이메일 수신 외 다른 변수(계절·프로모션 등)가 구매 변화에 영향을 줄 수 있어 단변량 처리 효과 검증의 한계가 있다.
- 이것이 인과관계인지 상관관계인지 발표에서 명확하게 구분돼야 한다.

### 감상평

업리프트 모델이라는 접근 자체가 12개 팀 중 가장 인과추론에 가까운 프레임워크였다. RCT 데이터를 사용해 처치 효과를 분리하려 한 설계 의도가 명확하고, T-Learner를 선택한 근거도 합리적이었다. 다만 교수님 지적처럼 "발송 비용 감소"가 핵심 가치인지, "효과 있는 고객에게 집중해 마케팅 ROI를 높이는 것"이 핵심 가치인지가 발표에서 혼재됐다. 관리자 입장에서의 비용 최적화에 집중했기 때문에 "손님 관점"(이메일을 받았을 때의 경험 개선)이 누락됐는데, B2C 마케팅 시스템에서 고객 경험을 배제하면 사용자 입장에서는 완전하지 않은 분석으로 보일 수 있다.

## 11조 — 경기장 매점 비전 기반 자동 결제 시스템

### 내용 요약

경기장 하프타임 15분의 매점 혼잡 문제를 해결하는 단일 카메라 기반 자동 결제 시스템이다. 기존 방식에서 고객 1인당 최소 1분이 소요되던 것을 10초로 단축하는 것이 목표다.

파이프라인: YOLOv8(음료 4종 탐지) → MediaPipe(손 추적) → ByteTrack(객체 ID 유지) → 존 경계 이탈 시 자동 결제. 화면은 선반 존(음료 배치)과 사용자 존(관객 이동)으로 분리된다. QR 코드로 입장 인증 후 음료를 집어 사용자 존 경계 밖으로 이동하면 장바구니에 자동 담김. 음료 4종(웰치스·콜라·판타·물)은 외형 차별성이 뚜렷한 MVP 검증용으로 선정했다. 성공 케이스(웰치스 홀딩 인식), 실패 케이스(콜라 — 초기부터 손실 0 수렴, 과적합)를 모두 발표에 포함했다. Amazon Go 대비 차별점: 무게 센서 없이 단일 카메라만 사용 → 도입 비용 대폭 절감.

### 교수님 코멘트 요약

- **한 개씩만 인식 가능한 제약** — 여러 개 동시에 집는 케이스가 미해결이다.
- Amazon Go와의 핵심 기술 축 차이(무게 센서 vs 단일 카메라)를 발표 **전면**에 제시해야 한다. 이것이 이 팀의 핵심 차별점이므로 발표 시작부터 강조해야 한다.
- **MVP 하나를 완벽히 검증하는 것이 우선**이며, 여러 기능을 동시에 다루지 말고 핵심 한 가지를 끝까지 완성하는 전략이 필요하다.

### 감상평

실패 영상(콜라 인식 실패)을 발표에 그대로 포함한 것이 오히려 발표의 신뢰도를 높였다. 감추지 않고 "왜 실패했는가"를 손실 수렴 그래프로 설명한 것은 솔직한 발표 태도다. 존 기반 자동 결제 트리거 방식도 직관적이고 실용적인 설계였다. 다만 성능 측면에서 단일 물체만 인식 가능하다는 제약이 실제 경기장 혼잡 환경에서 치명적인 한계다 — 경기장에서 여러 개를 동시에 집는 상황이 빈번하기 때문이다. Amazon Go 비교를 통해 "우리는 무게 센서 없이 같은 기능을 한다"는 포지셔닝을 발표 초반에 명확히 했다면 훨씬 강한 인상을 남겼을 것이다.

## 12조 — 앱 리뷰 기반 사용자 이탈 위험도 분류

### 내용 요약

토스·카카오페이·KB국민은행 구글 플레이 리뷰 900건을 수작업 라벨링해 KC-ELECTRA 파인튜닝으로 이탈 위험도를 3단계 분류하는 시스템이다. 앱 관리자가 어떤 문제를 먼저 개선할지, 경쟁사 대비 어떤 이슈가 있는지를 파악하도록 돕는다.

초기 계획은 Kaggle 데이터셋 + XLM-RoBERTa였지만 데이터 품질 문제(리뷰 15개 문장이 30만 번 반복, 이탈 확률 컬럼이 실제 내용과 불일치)로 직접 크롤링으로 전환했다. 라벨 기준: "삭제", "갈아탄다", "탈퇴" 등 명시적 이탈 언급을 클래스 3으로 정의하는 방식으로 수작업 라벨링. 초기 4분류 설계에서 클래스 2(약한 불만)와 3(강한 불만·이탈)의 경계가 모호해 최종 3분류로 재설계했다. 역번역 증강(한국어→일본어→한국어) + 클래스 가중치 적용. 베이스라인 TF-IDF+LR 정확도 57.3%에서 3분류 KC-ELECTRA 최종 정확도 85.4%, Cohen's Kappa 0.800으로 향상됐다. Streamlit: 앱 선택 → 감성 시계열 + 이탈 위험 리뷰 키워드 + 리뷰 필터링.

### 교수님 코멘트 요약

- **누구를 위한 시스템인지 명확히:** 앱 관리자가 개선 우선순위를 파악하고 경쟁사와 비교하는 용도임을 발표 처음에 위치시켜야 한다.
- 키워드 워드클라우드를 넘어 **리포팅 형태**로 제공해야 실무 활용이 가능하다. "이 키워드 때문에 이탈이 발생했고, 우리 앱은 이 부분, 경쟁사는 저 부분이 문제다"라는 인사이트 보고서 형태가 핵심 가치다.
- 경쟁사 비교 기능을 강화하라. 단순 시각화가 아니라 "경쟁사 대비 우리 앱의 차별 이슈"가 서비스의 실제 가치다.

### 감상평

라벨링 기준을 "삭제", "탈퇴" 같은 명시적 이탈 언급으로 정의한 것은 학습 데이터의 신뢰성을 높이는 합리적인 선택이다. 기존 Kaggle 데이터셋의 품질 문제를 발견하고 직접 크롤링으로 전환한 결단도 인상적이었다. 4분류 설계에서 3분류로 재설계할 때 "경계 모호성"이라는 명확한 근거를 제시한 것도 좋았다. 다만 교수님 지적처럼 현재 대시보드는 키워드를 보여주는 데 그치는데, 실제 앱 관리자에게 필요한 것은 "이 키워드가 이번 달 이탈 리뷰에서 얼마나 증가했고, 경쟁사와 비교하면 우리만의 문제인가"라는 문맥 있는 리포트다. 기술적 완성도는 높지만 "누구에게 어떤 결정을 돕는가"가 더 선명해져야 한다.

## 교수님 종합 마무리 코멘트

교수님은 12개 팀 발표를 모두 코멘트하며 공통 메시지를 정리했다. 핵심은 세 가지였다.

**첫째, 남의 발표가 내 경쟁력이다.** 12개 팀이 각기 다른 주제를 다뤘지만 데이터 누수·변수 선택·클래스 불균형·모델 선택 근거 등 동일한 함정이 반복됐다. 남의 발표에서 "저 문제가 내 모델에도 있지 않은가"를 확인하는 것이 AI 도구를 잘 다루는 사람의 역량이다.

**둘째, 모든 결정에 "왜"가 있어야 한다.** AUC를 메인 지표로 쓴 이유, 이 변수를 넣은 이유, 이 모델을 선택한 이유 — 각각에 비즈니스 맥락이 있어야 한다. "성능이 제일 높았기 때문"은 이유가 아니다.

**셋째, 발표는 리뷰어가 의문을 품지 않게 만드는 것이다.** 읽는 사람이 "이건 왜 안 했지?"라는 질문이 생기는 순간 코멘트가 붙는다. 한계점을 먼저 쓰는 것도 전략이다. 다음 발표는 인턴십처럼 — 대본 없이, 숫자의 의미를 스스로 해석하면서, "이 서비스는 누구에게 어떤 도움을 주기 위해 만들었는가"로 시작해야 한다.

## 전체 총평

12개 팀 발표를 통해 동일한 함정이 반복된다는 것을 직접 확인했다. 가장 많이 나온 문제는 세 가지다.

**데이터 무결성:** 3조는 미국 시장 시차 누수, 4조는 뉴스 데이터 합산 누수를 발표에서 직접 공개했다. 반면 10조는 라벨링 편향 문제가 날카롭게 지적됐다. 발표 전 스스로 발견하고 수정 계획을 밝힌 팀은 설득력이 높았다.

**"왜 이 숫자인가"의 부재:** AUC 0.53이 무작위보다 약간 높을 뿐임을 발표자 스스로 먼저 해석한 팀이 없었다. 성능 수치를 보여주는 것과 그 수치가 의미하는 것을 설명하는 것은 다르다. 교수님이 12개 팀 모두에 공통으로 요구한 것이 이 부분이었다.

**서비스 목적의 모호함:** "누가 이것을 쓰고, 어떤 결정을 내리게 되고, 그 결정이 맞았는지 어떻게 아는가"라는 흐름이 완결되지 않은 팀이 많았다. 8조의 "최적화" 제목, 12조의 키워드 시각화에 그친 대시보드가 대표적인 예다.

교수님의 마무리 메시지를 빌리면: **라이팅을 잘못하면 내용이 아무리 좋아도 의미가 없다.** 다음 발표에서는 "이 서비스는 누구에게 어떤 도움을 주기 위해 만들었는가"를 첫 문장으로 시작하고, 모든 선택에 이유가 있어야 한다.
