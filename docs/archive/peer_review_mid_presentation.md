## 1조 — MAS Lens: 학계 명성 편향 정량화

### 주제
동일 모델에서 명성 피처 유무에 따른 R² 차이(ΔR²)로 인용 편향 정량화.

### 내용 (발표 내용)
- CS 분야 2020년 논문 96만 → 1,550 이상 필터링 후 64만 편 (Semantic Scholar API)
- 텍스트: 1차 TF-IDF (GPU 없이 CPU 추론 가능, 서비스 배포 적합), 2차 SciBERT 계획
- 명성 피처 6개: h-index 최대·평균, 최고 저자 h-index, 공저자 수, 출판 등급, 참고 문헌 수 (타깃인 인용 수는 절대 미포함)
- 시간순 분할: 1~8월 학습, 10월 검증, 11~12월 테스트
- 결과: 텍스트만 R²=0.266 → 명성 추가 R²=0.471, **ΔR²=0.205** (95% CI: 0.201~0.209)
- 실험 A(원문) vs 실험 B(저자명·기관 마스킹): ΔR²=0.2051 vs 0.2050, 차이 0.0003 → 명성 효과는 텍스트 내 간접 단서가 아닌 명시적 피처에서만 작동
- 서비스 계획: 초록 입력 → 상위 몇% 예측 + SHAP 하이라이트 + 분야별 명성 효과 크기 시각화

### 교수님 코멘트
- **변수를 넣으면 R²는 기계적으로 올라간다** — 나머지 변수들이 변별력 없는 상태에서 명성 피처 하나가 높낮이를 줬을 가능성
- "단일 변수 기준으로 봤을 때 사실 명성만으로 된다는 얘기도 똑같잖아" — 명성 단독 모델 기준선이 먼저 필요
- **수치가 갖고 있는 의미를 해석해야 됨** — 숫자만 나열하지 말고 이 수치가 무엇을 의미하는지 직접 설명
- 남의 코멘트를 듣고 끝나는 게 아니라, 발표할 때 스스로 그 코멘트를 먼저 던질 수 있어야 함

### 우리 조 반영
- **피처 단독 기여도 선제 검증:** "날씨만 넣은 모델 vs 날씨 없는 모델" PR-AUC 차이를 Phase 2 ablation에서 수행. ΔR² 방식처럼 신뢰구간과 함께 제시.
- **숫자 해석 명시:** PR-AUC 수치가 "어떤 의미인가"를 발표에서 직접 설명. 단순 숫자 나열은 설득력이 없음.

## 2조 (우리 조) — 호텔 예약 취소 DSS + LLM 기반 협상 시스템

### 주제
취소 확률 예측 → 임계값 → Flexi 라우팅 + 오버부킹 수량 최적화 → walk 발생 시 LLM 기반 보상 협상.

### 내용 (실제 발표 내용)
- 오버부킹 리스크/리턴 구조 분석 후 ML 기반 최적화 시스템 설계
- 취소 확률 예측 → 임계값 설정 → 오버부킹 수량 결정 + 할인율 계산
- **LLM 기반 협상 시스템:** 기존 데이터가 없는 협상 영역에 LLM 적용, 고객 유형별 맞춤 전략
  - 레저 커플: 90유로 기준 수락률 급변 (앵커링 효과 관찰)
  - 가격 민감형: 46유로 근처 계단형 패턴 확인
- 협상 로그 축적 → ML 시스템으로 진화하는 데이터 플라이휠 구조
- Streamlit 앱 3탭: ① 예약 위험 관리 ② Flexi 라우팅 권장 ③ 신규 예약 관리
- RevPAR 81% 개선 수치 제시

### 교수님 코멘트
- "기존에 케글이나 테드린에 많이 올라와 있다고 들었는데 차이점이 뭐지" → **LLM 협상 시스템이 차별점** (기존 솔루션이 협상 이력을 다루지 못함)
- **법적 문제:** 진상 고객이 보상금을 노리고 끝까지 클레임할 수 있음 — "법적인 문제없니 진상 불응이 있을 수 있잖아요"
- 한국 고객 우선주의 환경에서 법적 근거 없이 오버부킹 시스템 운영이 실제로 가능한지 검토 필요
- "고객이 알고 나설 건데 — 제시문이나 법적 근거를 명시해 놓아야 실제로 쓸 수 있다"

### 우리 조 반영 (자기 반성)
- **Kaggle 차별점 명확화 필수:** "케글에 다 있다"는 비판은 최종 발표에서도 나올 것. ① 날씨 결합 ② 누수 컬럼 처리 ③ 비용 비대칭 임계값 ④ LLM 협상 시스템 — 4가지를 선행 노트북 대비 구체적으로 제시해야 함.
- **한국 법령 조사 필요:** 소비자보호법·호텔업 오버부킹 관련 법령 조사 후 시스템 사용 전제 조건을 명시. 발표 한계 섹션에 포함.
- **악용 시나리오 설계:** "매니저 최종 승인" 단계가 보상금 노리는 케이스를 방지하는 장치임을 발표에서 강조.

## 3조 — 한국 국고채 10년물 금리 일별 변화량 예측

### 주제
핀볼 로스 기반 분위수 회귀(q05/q50/q95)로 금리 일별 변화량 분포 예측.
90% 예측 구간을 제공해 리스크 관리와 직접 연결.

### 내용 (발표 내용)
- 22개 거시경제 후보 변수 → 3단계 필터(상관|r|≥0.05, VIF<12, p<0.05 그랜저 검정)로 8개 압축
- **데이터 누수 발견 및 수정:** 미국 변수 시차 14시간 → shift-1 적용 후 LSTM 방향 정확도 65.2% → 49.8%
- 파생 변수 5개 추가(한미 금리차·VIX 변화량·달러 변화율·위기 더미): 모두 shift-1 적용
- XGBoost v2 방향 정확도 61% (3-fold 평균), 라이브 대비 통계적 유의
- CQR 보정: 커버리지 85.3% → 98.4%, 단 구간 폭 11.6bp → 24.8bp 트레이드오프

### 교수님 코멘트
- **VIF 높다고 무조건 제거하면 안 됨:** 키·몸무게처럼 공선성 높은 변수 중 먼저 들어간 쪽이 SHAP을 독식 → 나머지가 의미 없어 보이는 착시
- "변수를 빼버리면 남아 있는 게 진짜 중요한 게 아니라 내가 빼고 나니까 걔가 남은 것" — VIF 높은 변수들을 도메인 지식으로 그루핑해서 대표 선택해야 함
- **예측 목적 vs 해석 목적 구분:** 예측이면 공선성은 큰 문제 아님, 해석이면 도메인 지식 기반 그루핑 후 대표 선택 필요
- "변수 선택 부분이 도메인 지식과 어울리는지 좀 더 신경 써야 될 거야"

### 우리 조 반영
- **VIF 맹목적 제거 금지:** 우리 날씨 변수 DROP(rain_sum 등 3개)은 VIF 기준이 아닌 "측정 중복" 도메인 근거로 결정 — 이 구분을 발표에서 명확히.
- **피처 드롭 근거 명시:** 예측 성능보다 "해석 오염 방지" 목적임을 발표 시 명확히.

## 4조 — 한국 상장기업 파산 예측 (CNN-LSTM + 기업 관계망)

### 주제
재무 시계열 + 기업 관계망 + 뉴스 감성 통합 모델로 1~2년 전 조기 부실 탐지.

### 내용 (발표 내용)
- DART 3,962개사 14년치 + 네이버 뉴스 8만 건 + 업종/재무유사도 기반 6.4만 엣지 관계망
- 불균형 40:1 → CTGAN으로 파산 74건→4,514건 증강 (4:1로 완화), **테스트셋은 40:1 원본 유지**
- Focal Loss(α=0.75, γ=2.0), 기업 단위 8:2 분할
- 성능: Altman 0.27 → LR 0.61 → LightGBM 0.64 → CNN-LSTM PR-AUC **0.79**
- **뉴스 데이터 누수 발견:** 전기간 합산 뉴스 사용 → 뉴스 카운트 Permutation Importance 1위(30~42%). 연도별 분리 미적용이 원인, 최우선 수정 예정

### 교수님 코멘트
- **긍정적:** "CNN-LSTM이 원래 가장 잘 나오고, 뉴스 누수 지적을 잘했고, 논문으로 쓸 수 있을 것 같다"
- CTGAN 처리 방식 확인: "데이터 개수만 늘리려고 한 거야?" → "40:1에서 3:1로 완화, 테스트셋은 40:1 그대로" → **올바른 방식 확인**
- "기존 모델 대비 너희가 뭐가 다른가 차이가 딱 극명하게 나타나면 좋겠어" — 기존 연구 한계와 자신의 차이점을 한 큐에 보여주는 발표 구성 권장

### 우리 조 반영
- **데이터 누수 체크리스트 유지:** 피처 추가 시마다 "예약 시점에 알 수 있는 정보인가?" 확인. deposit_type 누수 Week 1 제거가 올바른 사례.
- **기존 연구 대비 차이점 명문화:** 선행 노트북 5건 대비 ① 날씨 결합 ② 누수 처리 ③ 비용 비대칭 임계값 ④ Flexi 시스템을 수치와 함께 정리.

## 5조 — 머신러닝 기반 퀀트 펀드 의사결정 지원 시스템

### 주제
코스피 200 대비 5거래일 초과수익 방향 예측(이진 분류) → 확률 상위 5종목 포트폴리오.
절대 수익이 아닌 상대 성과를 예측 타겟으로 설정한 것이 핵심 차별점.

### 내용 (발표 내용)
- 코스피 200 유동성 상위 50종목, 종목·시장·업종·거시(환율·금리) 피처 통합
- 실험 1(분류 성능) → 실험 2(탑5 포트폴리오 백테스트) → 실험 3(워크 포워드 + 거시 오버레이) 3단계
- 2026-05-20 기준 실시간 예측: 두산로보틱스·한화오션·LG전자·삼성물산·한화에어로스페이스 탑5
- 3거래일 중간 점검: 상승 3종목, 하락 2종목 (최종 5거래일 검증 미완료)

### 교수님 코멘트
- **변수 선택 근거:** "제일 처음에 다른 사이트에 있는 코드의 변수를 잘 사용해" — 도메인 지식 기반인지, 기존 코드에서 그대로 가져온 건지 검토 필요
- **구조적 전환 구간 처리:** COVID 이후 이상치 구간이 이전 패턴과 구조가 달라 예측 불가 — "여기의 패턴으로 여기를 예측할 수 없어". 이상치 기점으로 구간 분리 학습 또는 제외 검토 필요
- "업종에 대한 기사 크롤링해서 업종별 가중치를 넣어본다든지" — 구조적 전환기 포착하는 외부 신호 필요

### 우리 조 반영
- **구조적 전환 구간 대비:** 호텔 데이터도 test가 여름 성수기 집중으로 계절 편중이 성능 과대평가 가능성. 월별 성능 분리 분석을 Phase 2에서 수행.
- **백테스트 이상의 검증:** Flexi 시뮬레이션이 "권장 액션 따랐을 때 vs 안 따랐을 때" 수익 차이를 보여줘야 발표 설득력이 생김.

## 6조 — 진로 목표 기반 전공 강의 추천 챗봇 (RAG)

### 주제
희망 진로 입력 → RAG 검색 → 로컬 LLM이 추천 이유 생성하는 강의 추천 챗봇.  
LLM이 수강 편람에 없는 내용을 추측하지 않도록 검색된 과목 정보를 근거로만 답변 생성.

### 내용
- SQLite(정형 데이터·개설 여부) + ChromaDB(과목 임베딩) 이중 스토리지
- 진로 선택 → 직업별 키워드 → 임베딩 검색 → 개설 여부 필터링 → LLM 추천 이유 생성
- 데모 모드(키워드 매칭) / API 모드(임베딩 유사도 검색) 분리 운영
- 채용 공고 기반 직업별 키워드 구축 계획 (임의 키워드의 주관성 제거)
- 로컬 LLM 선택 이유: API 비용 없이 독립 실행, 수강 편람 외부 전송 방지

### 교수님 코멘트
- 특정 직업군 카테고리 매칭 대신 **임베딩 유사도 측정**으로 전환 필요 — 사용자가 자유 입력 시 카테고리 밖의 키워드도 처리 가능해야 함
- 3~4학년 과목으로 제한하지 말고 **전체 학년** 확장 권장 (미적분·일반물리 같은 순수 기초만 제외)

### 우리 조 반영
- **정답 기준의 도메인 근거:** 6조가 채용 공고 JD 키워드로 정답 기준을 만든 것처럼, 우리 임계값도 "빈 방 손실 vs walk 보상 비용 비율"이라는 도메인 근거에서 나와야 함. 임의 설정이 아닌 수치 근거가 발표 설득력의 차이.
- **범위 확장 철학:** 처음엔 좁게, 구조는 확장 가능하게. Flexi 시스템도 현재 단일 임계값이지만, 호텔 유형(City/Resort)별 임계값이 달라질 수 있다는 확장성을 발표에서 언급.

## 7조 — 호텔 예약 취소 예측 기반 오버부킹 최적화

### 주제
XGBoost 취소 예측 → 확률 보정(Isotonic Regression) → 기대수익 함수 → 최적 오버부킹 수량 도출.  
SHAP은 목적이 아닌 수단, 최종 output은 "오늘 23개 객실 추가 판매"라는 단일 행동 지침.

### 내용
- 시간 분할(train/val/test 3구간), 세 구간 모두 취소율 37% 안정 확인
- XGBoost: ROC-AUC 0.9458, F1 0.8145, Brier Score 0.099, 32개 그리드서치
- 확률 보정: ECE 0.0477 → 0.0078 (6.1배 개선, Isotonic Regression)
- 기대수익 함수: ADR × (1 - p_cancel) - 보상비용 × p_arrive
- 민감도 분석: ADR 10~25만원 × 보상배수 1.0~2.0 그리드 → 최적 오버부킹 수량 변화폭 1.5% 미만
- 생존 분석 계획: 체크인 60/30/7일 전 시점별 확률 재조정으로 동적 오버부킹 관리
- 한국 취소 보상 정책 반영 예정: 7일/5일/3일/당일 배수 차등 적용

### 교수님 코멘트
- **악의적 사용 케이스 고려 필수:** 손님이 오버부킹 보상금을 노리고 의도적으로 클레임하는 경우
- 시스템 사용 전제 조건(법적 근거, 적용 한계)을 명시해야 호텔이 실제로 도입 가능
- "단서를 달아야" 시스템이 책임 있게 운영됨 — 조건 없는 추천 도구는 현장 거부됨

### 우리 조 반영
- **7조 vs 2조 차별화 재점검:** 7조는 "최적 오버부킹 수량" output, 우리는 "개별 예약 위험도 + SHAP 근거 + Flexi 라우팅 권장" output — 다른 레이어에서 작동하는 시스템. 발표에서 이 구분을 명확히.
- **확률 보정 검토:** 7조가 Isotonic으로 ECE 6.1배 개선. 우리 XGBoost/LightGBM 확률 값의 캘리브레이션 여부를 Phase 2에서 검토. Flexi 임계값 기반 라우팅은 확률 품질에 직접 영향.
- **악의적 사용 대비:** 우리도 "취소 확률 높은 손님을 Flexi로 분류"가 불공정 분류 오해를 살 수 있음. GDPR Art.22 + "권장이지 강제 아님" UI가 이미 설계됨 → 발표에서 명시.
- **생존 분석 아이디어:** 7조의 시점별 확률 업데이트는 Phase 2에서 우리에도 적용 가능. 체크인 D-7 시점 DSS 실행이 더 높은 정확도를 줄 수 있는지 탐색.

## 8조 — 서울시 따릉이 수요 예측 및 재배치 최적화

### 주제
시간/날씨/요일/대여소 특성으로 따릉이 수요 예측 → 재배치 전략 최적화.  
출퇴근 시간대 급등, 새벽 극소 등 비선형 패턴을 앙상블 모델로 포착.

### 내용
- 핵심 피처: 대여소별 시간대·요일 평균 수요 (입지 특성 대리변수)
- Lag 피처 (1시간/24시간/7일 전 실수요) + 기온·강수량·습도 + 출퇴근·공휴일 변수
- Demand Ratio 파생 변수 (규모 효과 제거, 순수 시간대별 패턴 표준화)
- 시간 순환 인코딩 (sin/cos): 23시-00시, 12월-1월 연속성 보장
- 새벽(00~05시)과 주간 분리 학습 (MAPE 극단값 왜곡 방지)
- Walk-Forward 4-fold 검증 (사계절 패턴 전체 학습)
- 단기: LightGBM + XGBoost 앙상블 / 장기: ExtraTree

### 교수님 코멘트
- **근본적 문제:** 이동 전후 데이터 없이 "진짜 수요 부족"(빈 대여소에 오려다 실패한 건수)을 알 수 없음. 현재 모델은 이미 일어난 대여 수를 추적하는 것
- 제목은 **"현재 수요량 예측"**이 더 정확하며, 실제 재배치 효과 검증(이동 전후 비교) 없이 최적화 주장이 성립하지 않음

### 우리 조 반영
- **"예측"과 "효과" 분리:** 우리도 PR-AUC 높다고 매출이 늘지 않음. Flexi 시뮬레이션(RevPAR 개선 + walk_rate < 2%)이 "예측 → 액션 → 결과" 사이클의 핵심. 8조의 한계가 정확히 우리가 피해야 할 지점.
- **Week 4 시뮬레이션이 필수:** 발표에서 PR-AUC만 보여주고 끝나면 8조와 같은 비판을 받음. "예측을 써서 무엇이 달라졌는가"를 수치로 보여줘야 함.

## 9조 — AI 기반 와인 병 포장 공정 품질관리

### 주제
제조 공정 5단계(병 투입→캡 체결→라벨→패키지→출하)에서 불량 탐지 + 장비 상태 예측 + 의사결정 지원.  
중간 검사 도입 여부(비용 vs 불량 감지 효과)를 시나리오 비교로 정량화.

### 내용
- 이미지 결함 탐지: Random Forest (RGB·색상 히스토그램 피처)
- 설비 이상 탐지: Random Forest (온도·회전속도·토크·공급압 기반 파생 변수)
- 마르코프 프로세스: 정상→위험→고장 상태 전이 확률 행렬 (Stationary 가정)
- 잔여 수명 예측: Random Forest (실제 유지보수 데이터 기반)
- 비교 시나리오: 중간 검사 있음 vs 없음 × 부분 정지 vs 전체 정지
- 결과: 문제 공정만 부분 정지하는 전략이 전체 라인 정지 대비 2배 이상 비용 효율

### 교수님 코멘트
- **두 효과가 혼재:** 장비 수명 감소 → 불량률 증가의 경로와 불량 탐지 자체가 섞여 있음. 장비 상태 정상인데 불량 발생(또는 그 반대) = **미스매치 기반 의사결정**을 보완해야 함
- 발표에서 시스템 목적이 "비용 절감"임을 핵심에 명확히 위치시킬 것

### 우리 조 반영
- **시나리오 비교 구조 참고:** 9조의 "A안 vs B안 × 비용 기준" 비교가 발표 설득력에 효과적. Flexi 시뮬레이션도 "Flexi 없음 vs Flexi 있음" × "walk_rate 시나리오별" 비교로 구성.
- **날씨 효과의 혼재:** 비 오는 날 취소 증가 = 날씨 직접 영향 + 비 오는 날 예약 자체가 저위험 고객 편향(선택 편향). Phase 2 ablation 설계에서 이 구분 고려.

## 10조 — 이메일 마케팅 업리프트 모델 (T-Learner)

### 주제
할인 이메일 수신이 구매 행동을 변화시키는 고객(Persuadables) 9.6%만 식별해 타겟팅.  
전체 발송 대비 상위 15% 타겟팅 시 발송량 85% 감소 + 순이익 82% 증가 + ROI 43.8배.

### 내용
- 데이터: Hillstrom Email Marketing 실험 데이터, 64,000명 랜덤 배정 A/B 테스트 3그룹

- T-Learner 선택: 발송/미발송 그룹을 별도 모델로 학습 → 업리프트 분포가 가장 신뢰할 수 있음
- 수익 계산: (이메일 수신 매출 - 대조군 매출) × 마진 30% - 발송비용 $0.05/건
- Streamlit 대시보드: 파일 업로드 → 고객별 업리프트 스코어 + 타겟 추천 자동 출력

### 교수님 코멘트
- "어차피 살 사람(Sure Things)은 이메일 비용만 줄이는 것" — 비용 절감 이상의 가치(충성도 변화, 재구매율)가 있는가?
- 이메일 수신 외 다른 변수(계절·프로모션 등)가 구매 변화에 영향을 줄 수 있음 — 단변량 처리 효과 검증의 한계
- 인과관계인지 상관관계인지 구분이 발표에서 모호함

### 우리 조 반영

- **업리프트 프레임을 우리 발표에 적용:** "Flexi 제공 여부가 실제 walk_rate를 줄이는가"를 검증하는 것이 우리의 업리프트 측정. 10조 프레임워크를 호텔 맥락에 맞게 재해석 가능.

## 12조 — 앱 리뷰 기반 사용자 이탈 위험도 분류

### 주제
토스·카카오페이·국민은행 구글 플레이 리뷰 900건 수작업 라벨링 → KC-ELECTRA 파인튜닝으로 이탈 위험도 3단계 분류.  
앱 관리자가 선제 대응하고 경쟁사 대비 개선 우선순위를 파악하는 시스템.

### 내용
- Google Play Scraper로 3개 앱 × 300건 크롤링 (앱명·별점·리뷰 텍스트)
- 수작업 4분류: 긍정(0) / 중립(1) / 약한 불만(2) / 강한 불만·이탈 언급(3)
- 클래스 2↔3 경계 모호 → **3분류로 재설계** (이탈 위험 / 불만 / 긍정)
- 역번역 증강(한국어→일본어→한국어) + 클래스 가중치 조정
- 베이스라인: TF-IDF + LR 정확도 57.3%, 매크로 F1 47.6%
- KC-ELECTRA 4분류 정확도 71.3% → 클래스 1/3 리콜 거의 0%
- 3분류 KC-ELECTRA 최종: 정확도 85.4%, Cohen's Kappa 0.800
- Streamlit: 앱 선택 → 감성 시계열 + 이탈 위험 리뷰 키워드 + 리뷰 필터링

### 교수님 코멘트
- **누구를 위한 시스템인지 명확히:** 앱 관리자 → 개선 우선순위 파악 + 경쟁사 대비 분석
- 키워드 워드클라우드를 넘어 **리포팅 형태**로 제공해야 실무 활용 가능
- 경쟁사 비교 기능 강화: "우리 앱은 이 키워드가 문제, 경쟁사는 저 키워드가 문제" — 비교 인사이트가 핵심 가치

### 우리 조 반영
- **라벨 설계의 신뢰성:** 수작업 라벨링 편향 문제처럼, 우리 임계값도 "임의적"이라는 비판을 받을 수 있음. 빈 방 손실 vs walk 보상 비용 비율을 문헌 또는 업계 데이터로 뒷받침해야 함.
- **경쟁 시스템 차별화:** 12조가 경쟁사(토스 vs 카카오페이) 비교를 강화하듯, 우리도 7조와의 차별점(개별 예약 위험 설명 + Flexi 구조)을 발표에서 명확히.
- **클래스 불균형 처리 참고:** 3단계 위험도 분류 구조가 우리 취소 위험 레벨 분류와 유사. 가중치 + 역번역 증강 전략을 우리 모델 클래스 불균형(37% 취소)에도 참고.

## 교수님 종합 마무리 코멘트

### 핵심 메시지
- **남의 발표가 내 경쟁력:** 12개 팀이 각자 다른 주제를 다루지만 데이터 누수·변수 선택·클래스 불균형 등 동일한 함정이 반복됨. 남의 발표를 들으며 "저게 내 모델에도 있지 않나?"를 확인하는 것이 AI 도구를 잘 쓰는 사람의 역량.
- **"왜"가 없으면 발표가 아님:** 모델 선택, 지표 선택, 변수 드롭 — 모든 결정에 "왜"가 있어야 함. "AUC가 높았기 때문"은 이유가 아님. 비즈니스 관점에서 "왜 이 지표가 중요한가"까지 답해야 함.
- **PPT = 리뷰어가 의문을 품지 않게 만드는 것:** 읽는 사람이 "이건 왜 안 했지?"가 생기는 순간 코멘트가 생김. 그 의문이 발표 안에서 미리 해소되어야 좋은 발표. 한계점을 먼저 쓰는 것도 전략.
- **다음 발표는 인턴십처럼:** 대본 없이, 숫자의 의미를 직접 해석하면서, "이 서비스는 누구에게 어떤 도움을 주기 위해 만들었는가"로 시작하는 발표.

### 우리 조 반영
- 발표 한 줄 정의(이 발표 내내 흔들리지 않아야 하는 것): **"취소 위험 있는 예약을 Flexi 풀로 유도해 빈 방 손실을 줄이고, 매니저에게 SHAP 근거와 기대 RevPAR 개선폭을 제공한다"**
- 최종 발표 흐름: 문제(호텔 빈 방 손실) → 접근(취소 위험 예측 + Flexi 라우팅) → 근거(SHAP) → 시뮬레이션 결과(RevPAR X% 개선, walk_rate Y%) → 한계(날씨 인과관계 미확정, 포르투갈 데이터)
- "왜 PR-AUC인가", "왜 시간 분할인가", "왜 날씨를 넣었는가" — Q&A에서 나올 모든 "왜"를 발표 슬라이드 안에서 선제적으로 해소할 것
