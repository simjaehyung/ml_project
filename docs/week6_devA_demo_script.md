## 🎬 Demo 설명 멘트 (검증 결과 기반, 약 40초)

> PM이 라이브로 LLM 에이전트 → PMS → DSS 흐름을 실행하는 동안, 그 위에 얹는 설명.

"지금 보시는 건 LLM 손님 에이전트가 실제로 예약을 넣는 장면입니다. 흐름을 따라가 보면 —

**손님이 예약하면**, PMS가 손님 언어를 — 국적·식사플랜 같은 걸 — DSS가 이해하는 형식으로 번역합니다. **DSS는 LightGBM으로 취소 위험을 예측**하고, SHAP으로 *왜 위험한지*까지 계산합니다.

여기서 핵심은 **정보 분리**입니다. *(info_separation_diagram 슬라이드)* 같은 예약인데 — **손님은 'Flexi 요금 14.3% 할인'만** 봅니다. 위험점수 0.94, SHAP 분석은 **호텔 내부만** 봅니다. 손님은 자기가 '고위험으로 분류됐다'는 걸 절대 알 수 없습니다.

그리고 **최종 결정은 항상 매니저**입니다. AI는 'Flexi 권장'까지만 하고, 실행은 사람이 승인합니다."

## 🔑 검증으로 *직접 확인한* 숫자 (믿을 수 있는 라이브 데이터)

| 항목 | 값 | 출처 |
|------|-----|------|
| 고위험 예약 위험점수 | **0.94 (HIGH)** | DSS POST 응답 |
| Flexi 할인율 (내부) | 16.4% | DSS `discount_rate` |
| 손님에게 보이는 할인 | **14.3%** | PMS 확인서 |
| 손님 확인번호 | PMS-535BBE | PMS 응답 |
| 총 금액 | €257 (3박) | PMS 확인서 |
| SHAP top 3 | 포르투갈 국적 / 리드타임 182일 / 특별요청 0 | DSS 응답 |

→ 모두 *시드 데이터가 아니라 실제 모델 추론 결과*. "정말 돌아간다"의 증거.

## 🎤 Q&A 대비 (Dev A 담당 가능 질문)

**Q: "이거 진짜로 작동하는 건가요, 화면만 만든 건가요?"**
> "실제 작동합니다. 제가 직접 검증했는데, 서버 두 개를 띄우고 손님 예약을 보내면 LightGBM이 위험점수 0.94를 계산하고, SHAP으로 포르투갈 국적·리드타임 182일이 위험 요인이라고 설명하고, Flexi 할인율까지 자동 산출합니다. 시드 데이터가 아니라 실시간 모델 추론입니다."

**Q: "손님이 자기가 고위험으로 분류된 걸 알면 불쾌하지 않나요?"**
> "그래서 정보 분리를 설계했습니다. 손님 화면엔 'Flexi 요금 14.3% 할인'만 보이고, 위험점수·SHAP은 호텔 내부만 봅니다. 손님은 자기가 분류됐다는 사실 자체를 알 수 없습니다. 검증에서 실제로 손님 확인서에 위험점수가 노출되지 않는 걸 확인했습니다."

**Q: "법적으로 문제 없나요?"** (나리 파트와 연결)
> "기존 오버부킹의 법적 문제는 '체크인 당일 사후 통보'인데, 우리는 손님이 예약 시점에 Flexi 요금에 사전 동의하는 구조라 계약 불이행이 성립하지 않습니다. 그리고 GDPR Art.22 — 자동화된 결정 금지 — 에 대응해 최종 결정은 매니저 승인을 거칩니다. AI는 권장만 합니다."

**Q: "PMS랑 DSS가 어떻게 통신하나요?"**
> "PMS가 손님 언어로 받은 예약을 DSS 스키마로 번역해서 REST API로 호출하고, DSS가 위험점수와 SHAP을 돌려주면 PMS가 다시 손님 언어로 재번역합니다. 두 서버가 분리돼 있어서 손님용 PMS와 내부용 DSS의 정보 경계가 코드 레벨에서 나뉩니다."
