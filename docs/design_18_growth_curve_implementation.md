## 2. 실험 설계 (2026-06-04 토론 확정)

```
시간 축    : 주 단위 누적창(주력) + 슬라이딩창(최근 26주, robustness 오버레이)
라벨 규칙  : point-in-time — arrival_week ≤ t 인 예약만 학습 (look-ahead 차단)
모델       : Dummy, LR(스케일), RF, XGBoost, LightGBM
HP 정책    : 구간별 경량 재튜닝(규제축 1개), train 내부 시간순 holdout(마지막 20%)로 선택
평가셋     : 고정 시간기반 test 40,687행 (여름 편중 — 각주)
반복       : 트리 시드 다회(42·7·123) + test Bootstrap 리샘플
KPI        : 3층 (4절)
산출물     : x=누적 주차, y=PR-AUC, 5곡선 + CI 밴드 + 슬라이딩 오버레이 + 전환주차 W
```

### 2.1 누적창 = 주력, 슬라이딩창 = robustness (합의 1)

콜드스타트 호텔은 **버릴 데이터가 없으므로 누적창이 현실**. 단 곡선 상승이 "표본 수 N"인지 "최신성/분포이동"인지 구분하려면 슬라이딩창(오래된 데이터 버림)을 겹쳐 본다. 두 곡선이 비슷 → 상승은 N 효과 / 슬라이딩 우월 → 최신성이 핵심. 어느 쪽이든 방어 가능.

### 2.2 point-in-time 라벨 — 정확한 정의 (합의 2)

취소 라벨은 예약 시점이 아니라 **결과 확정 시점**에 알 수 있다. t주차에 학습 가능한 데이터 = "t까지 예약된 것"이 아니라 **"t까지 결과가 확정된 것"**.

- **구현:** 학습 적격 = `arrival_week ≤ t`. `arrival_week ≥ booking_week`이므로 이는 `booking_week ≤ t`를 자동 함의 → **미래 예약 훔쳐보기(look-ahead) 차단.**
- **결과 확정 시점 proxy = 도착일.** `reservation_status_date`(취소 확정일)가 누수로 DROP되어 "언제 취소가 확정됐는지" 모른다. 따라서 도착일을 결과 확정의 **보수적 상한**으로 둔다(사전취소는 더 일찍이지만, 도착일 기준이면 확실히 확정됨).
- **부작용 = 인사이트:** t 시점에 "예약됐지만 미도착(booking ≤ t < arrival)"인 건은 라벨 미확정이라 제외된다. 초기 주차일수록 장기 선예약(=고위험 핵심군)이 학습에서 빠진다. **숨기지 않고 슬라이드에 쓴다**: "콜드스타트 초기엔 단기예약만 라벨링되어 모델이 장기-고위험을 늦게 배운다."

### 2.3 구간별 경량 재튜닝 (합의 3)

full-data HP를 1주차 소표본에 그대로 꽂으면 "약한 게 아니라 굶긴 비교". 그렇다고 풀 그리드 nested CV는 폭발 + 소표본 분산. **절충: 모델당 규제축 1개만 구간별 조정.**

| 모델 | 규제축 | 그리드 |
|------|--------|--------|
| LR | C | {0.1, 1, 10} |
| RF | max_depth | {None, 10, 20} |
| XGBoost | max_depth | {3, 6, 9} |
| LightGBM | num_leaves | {15, 31, 63} |

선택 기준 = **train 내부 시간순 holdout(마지막 20%)의 PR-AUC** → test 누수 없음. holdout이 50건 미만이거나 단일 클래스면 기본값 사용. 선택 후 train_sub 전체로 재학습. **발표에 "구간별 경량 재튜닝(규제축 1개)" 정책 명시** — 안 쓰면 "고정 HP로 굶긴 비교 아니냐" 공격에 노출.

## 3. KPI 3층 (합의 4 — 핵심)

| 층 | KPI | 역할 | 구현 |
|----|-----|------|------|
| **1차 (모델 선정)** | PR-AUC + Bootstrap 95% CI | 순위 품질, 구간별 승자 판정 | `average_precision_score` + test 리샘플 1,000회 |
| **2차 (배포 준비도)** | Brier score | 확률 보정 — Flexi 임계 안전성 | `brier_score_loss` |
| **보조 (사업 해석)** | 운영 임계 expected cost (비용비 sweep) | RevPAR/walk-rate 연결, 가정 명시 | 임계 0.65, c_fn/c_fp ∈ {2,5,10} |

- **왜 PR-AUC만으론 부족한가:** 순위만 봄. 소표본 모델은 순위는 그럴듯해도 확률이 부풀어/쪼그라들어 임계 0.65에서 walk-rate 폭증할 수 있다 → Brier로 거른다.
- **성장 곡선의 발견:** calibration(Brier)은 PR-AUC보다 **늦게 수렴**하는 경향 → "순위는 일찍, 확률 신뢰는 늦게" = 초기엔 Flexi 임계를 보수적으로.
- **expected cost는 보조로만:** 비용비·임계 가정을 수입하므로 1차 KPI로 쓰면 결론이 가정에 종속. 반드시 **비용비를 sweep**해서 범위로 제시.

## 4. 핵심 산출물 — 전환 주차 W (합의 5)

곡선 5개보다 **숫자 하나**가 발표에서 세다: **"약 W주차 / 약 N건 이후 부스팅으로 갈아타라."**

- **정의:** 누적창에서 **LightGBM CI 하한 > LR CI 상한**이 되는 첫 주차 (= 통계적으로 부스팅이 단순모델을 추월).
- **정직성 규율:** 곡선이 교차해도 CI가 겹치면 "교차"라 부르지 않는다(노이즈). 그 사이 구간은 **"구분 불가(tie)"**로 표기.
- **각주 필수:** W는 **여름 편중 test셋**에 의존하는 값. 우리 test가 성수기라 고위험 패턴이 과대표집돼 있다.

## 5. 발표에서 라이선스되는 주장 (합의 6)

> "고정된 (여름 편중) 평가셋에 대해, 우리 호텔 데이터가 주 단위로 쌓일 때 **모델 클래스의 최적점이 이동**하며, 약 W주차에 부스팅이 단순모델을 **통계적으로** 추월한다. 따라서 **성장형 시스템은 모델을 고정해선 안 된다.**
> 그리고 순위(PR-AUC)는 일찍 수렴하지만 **확률 보정(Brier)은 늦게 와서, 초기엔 Flexi 임계를 보수적으로** 가져가야 한다."

- 정량은 실데이터가 책임진다(하이쿠 미사용 — design_17 오염 금지).
- LightGBM 0.8189은 버려지지 않고 **full-data 구간 승자 + 곡선 앵커**로 생존(design_17 결정 #1·#3).
- 발표 임팩트: 기존 Slide 05(정적 비교표) → **"데이터가 모델을 고르게 한다" 동적 그래프**로 격상.
