## 001. TabLLM (arXiv 2210.10723, 2022)
**Few-shot Classification of Tabular Data with Large Language Models**  
Hegselmann et al. | NeurIPS 2023

### 왜 이 논문이 나왔는가

레이블된 데이터가 극히 적은 상황에서 테이블 예측을 어떻게 하느냐는 문제다. 희귀질환처럼 데이터 자체가 없는 경우, 기존 XGBoost·LightGBM은 아무것도 못 한다. LLM은 이미 세상 지식을 대량 학습했으니 레이블 없이도 판단할 수 있지 않을까 — 이게 출발점이다.

### 핵심 아이디어: 직렬화(Serialization)

테이블 한 행 → 자연어 문자열로 변환 → 질문 붙이기 → LLM이 Yes/No 출력.

```
[원본 행]
Age=35, Education=Masters, Capital_Gain=5000

[List Template]
"age: 35, education: Masters, capital_gain: 5000"

[Text Template]  ← 제로샷에서 가장 강함
"The age is 35. The education is Masters. The capital gain is 5000."

[LLM 생성 자연어]  ← 오히려 나쁨
"This person is 35 years old with a Master's degree..."
→ 환각(hallucination)이 섞여 들어옴

[최종 프롬프트]
"The age is 35. The education is Masters. The capital gain is 5000.
Does this person make more than $50,000? Yes or No?"
```

9가지 직렬화 방법을 비교 실험. LLM이 생성한 "자연스러운" 문장은 오히려 성능을 낮췄다 — LLM이 해석을 추가하면 노이즈가 된다는 발견.

### 실험 설계

- 공개 데이터셋 9개 + 대규모 의료 청구 데이터
- 비교 대상: Logistic Regression, XGBoost, LightGBM, TabNet, TabPFN, GPT-3
- 레이블 수: 0, 4, 8, 16, 32, 64, 128, 256, 512, 전체
- 평가: AUC

### 핵심 결과

**레이블 수별 구간이 명확하게 갈린다:**
```
0 ~ 256건:   TabLLM > XGBoost  (LLM이 사전 지식으로 보완)
256건 이상:  XGBoost가 따라잡기 시작
전체 데이터: XGBoost ≥ TabLLM
```

**직렬화 방식 비교 (제로샷 기준):**
- Text Template > List Template (+0.05 AUC)
- LLM 생성 문장 < List Template (환각 오염)
- 열 이름 제거 시 -0.15 AUC
- 열-값 대응 섞으면 -0.25 AUC → 열 이름의 의미가 핵심

**LLM이 실제로 중요한 피처를 보고 있는가:**  
Income 데이터셋에서 TabLLM의 상위 5개 피처가 LR의 상위 7개에 모두 포함.  
의료 데이터에서 상위 피처들이 실제 임상 위험도(RR>2.0)와 일치.  
→ LLM이 임의로 답하는 게 아니라 의미 있는 피처를 실제로 참조한다.

### 저자 인정 한계

| 한계 | 우리 프로젝트 해당 여부 |
|---|---|
| 토큰 한계 — 피처 많으면 잘림 | 해당. SHAP 상위 피처만 선택하는 이유 |
| 도메인 지식 의존 — 모른 도메인은 약함 | Claim 1이 바로 이걸 확인하는 실험 |
| 계산 비용 | Qwen2.5-14B 로컬 실행으로 대응 |
| LLM 학습 시점 편향 | 2017년 데이터 vs 현재 LLM 학습 데이터 간극 존재 |

### 우리 프로젝트에 주는 것

- Claim 1 실험의 직접 선례 — 제로샷 테이블 예측이 작동한다는 근거
- 프롬프트 설계 원칙: Text Template 형식, 해석 언어 배제
- 열 이름이 의미 있어야 함 → `lead_time: 180`보다 `Days before check-in: 180`

## 002. ZET-LLM + 직렬화 심화 연구 (2022-2023)
**Surprisingly Simple: LLMs are Zero-Shot Feature Extractors (OpenReview)**  
**Towards Better Serialization of Tabular Data (arXiv 2312.12464, 2023)**

### 왜 이 논문들이 나왔는가

TabLLM이 보여준 가능성에 연구자들이 달려들었다. 두 가지 질문이 생겼기 때문이다.

1. **LLM을 텍스트 생성기가 아니라 피처 추출기로 써도 되지 않을까?** (ZET-LLM)
2. **직렬화 방식이 성능을 얼마나 바꾸는가? 최적이 있는가?** (Towards Better Serialization)

### ZET-LLM의 핵심 아이디어

TabLLM은 LLM을 텍스트 생성기로 쓴다 — "Yes/No를 출력하게" 한다. ZET-LLM은 다른 방향을 택한다.

> "LLM을 분류기가 아니라 **임베딩 모델**로 쓰자."

**Feature-wise Serialization:**  
각 피처를 하나의 토큰으로 표현하고, 모든 토큰을 합쳐서 샘플 전체 임베딩을 만든다.

```
[TabLLM 방식]
"The age is 35. The education is Masters." → LLM → "Yes"

[ZET-LLM 방식]
"age: 35" → 토큰 임베딩
"education: Masters" → 토큰 임베딩
"capital_gain: 5000" → 토큰 임베딩
        ↓ 결합
   샘플 임베딩 벡터 → 분류기 헤드
```

**Bidirectional Attention:**  
일반 LLM은 왼쪽→오른쪽으로만 본다(autoregressive masking). ZET-LLM은 이 마스킹을 제거해서 양방향으로 모든 피처를 동시에 볼 수 있게 만든다.

**결과:** 피처 수가 많은 데이터셋(SAD 등)에서 sample-wise 직렬화(TabLLM 방식)보다 일관되게 우수. 혼합 모달 데이터(수치 + 범주 혼합)에서 특히 강점.

### Towards Better Serialization이 발견한 것

TabLLM 이후 직렬화 방법론을 체계적으로 비교한 연구.

**놀라운 발견 — LaTeX 형식이 제일 잘 된다:**
```
[Text Template]
"The age is 35. The education is Masters."
AUC: 0.51 (zero-shot 기준)

[LaTeX 형식]
\hline 35 & Masters & 5000 \\
AUC: 0.686 (zero-shot 기준)
```

왜 LaTeX가 좋은가? 자연어에 가까울수록 좋다는 직관이 틀렸다. LLM은 **구조적 일관성**에서 패턴을 더 잘 잡는다. LaTeX는 구조가 명확하고, 헤더를 줄여 메모리도 66% 절감.

**피처 순서의 영향:**  
상관관계 기준 중요도 상위 4개 피처에 "Critically" 접두사를 붙이는 실험 → 제한적 효과. 직렬화 방식 자체가 더 중요하다.

**TabLLM의 실용적 한계:**  
32샷 이후 CUDA 메모리 부족. 텍스트 템플릿은 토큰 수가 너무 많아서 컬럼 수 많은 데이터에 취약.

### 두 논문이 합쳐서 주는 인사이트

```
TabLLM:  자연어에 가까울수록 좋다      → 부분적으로 맞음
ZET-LLM: 피처별 임베딩이 더 깔끔하다  → 피처 많을 때 유리
Better Serialization: 구조적 일관성이 핵심  → 자연어보다 명확한 포맷
```

세 연구가 공통으로 합의하는 것:
1. **열 이름(의미)이 있어야 한다** — 숫자만으로는 LLM이 맥락을 못 잡음
2. **LLM이 생성한 해석을 넣으면 나빠진다** — TabLLM과 동일한 결론
3. **피처가 많으면 선택이 필요하다** — 토큰 한계 실용적 제약

### 우리 프로젝트에 주는 것

| 발견 | design_13 적용 |
|---|---|
| 구조적 일관성이 자연어보다 유리할 수 있음 | 블록2 variant A(수치 나열)와 B(자연어) 비교 실험 필수 |
| 피처 순서 효과 제한적 | SHAP 순서 실험(variant C)은 낮은 우선순위 |
| 피처가 많으면 선택 필요 | SHAP 상위 7개로 제한하는 것이 타당 |
| LaTeX 같은 구조 형식이 의외로 강함 | variant D로 추가 가능 (현재 문서에는 없음) |

## 003. ProtoLLM (arXiv 2508.09263, 2025년 8월)
**LLM Empowered Prototype Learning for Zero and Few-Shot Tasks on Tabular Data**

### 왜 이 논문이 나왔는가

TabLLM이 예시(few-shot)가 필요했고, 그 예시를 LLM에 노출하면 데이터 유출 위험이 생긴다. ProtoLLM은 그 문제를 정면으로 뚫는다: **예시 없이** 오직 태스크 설명과 피처 설명만으로 제로샷 분류를 한다.

추가 동기: 기존 방법들은 테스트 샘플마다 LLM을 호출해야 했다(추론 비용 높음). ProtoLLM은 학습 전 단계에서 LLM을 한 번만 쓰고, 추론 시에는 LLM 없이 작동한다.

### 핵심 아이디어: Prototype = LLM 지식으로 만든 클래스 대표 벡터

```
[기존 Prototype Learning]
  실제 레이블 데이터 → 클래스별 평균 벡터(프로토타입) → 거리로 분류

[ProtoLLM]
  LLM에게 묻는다: "income>50K인 사람의 typical한 특성값은?"
  → JSON 응답: {"education": ["Masters", "Doctorate"], "capital_gain": [5000, 7000]}
  → 이걸로 프로토타입 구성 → 레이블 없이 분류
```

**3단계 파이프라인:**

1. **피처별 독립 생성** — 모든 피처를 한꺼번에 묻지 않는다. 피처마다 따로 묻는다 (복잡한 상호작용에서 LLM이 헷갈리는 것 방지)

2. **특성 중요도 생성** — "이 피처들 중 분류에 중요한 것 순위를 매겨줘" → 가중치 벡터

3. **프로토타입 구성** — 피처별 LLM 출력값 × 가중치 → 클래스 대표 벡터

**퓨샷 확장:** 실제 데이터가 조금 있으면 LLM 사전 지식 + 실제 데이터 평균으로 프로토타입 보정

### 실험 설계

- 10개 데이터셋(Adult, Bank, Diabetes, Heart 등)
- 비교 대상: TabLLM, FeatLLM, XGBoost, TabPFN, In-context LLM 등
- 0~64 shot 구간 평가, AUC 지표

### 핵심 결과

**제로샷 AUC 평균:**
```
ProtoLLM:  76.09  ← 1위
TabLLM:    69.82
DSPy:      55.96
```

**4~64샷 구간 모두 1위 유지.** 64샷에서 FeatLLM과 격차 1.6 AUC.

**Ablation 결과:**
- 예시 제거 효과 가장 큼 (예시 넣으면 오히려 4-shot에서 -5.4 AUC)
- 피처 분해(독립 생성) 없애면 -3 AUC
- 가중치 없애면 -1 AUC

→ "예시를 안 쓰는 것"이 핵심이었다. 적은 레이블로는 LLM 사전 지식이 더 신뢰할 만하다.

**도메인 지식 의존:**
- 잘 됨: Adult(소득), Bank(금융), NHANES(건강) — LLM이 이미 아는 도메인
- 안 됨: Cultivars(농업 품종) — LLM이 모르는 특수 도메인

### 저자 인정 한계

| 한계 | 내용 |
|---|---|
| 도메인 지식 필요 | 모르는 도메인에서 57 AUC까지 떨어짐 |
| 수치 범위 추정 불안정 | LLM이 실제 데이터 범위 밖 값을 제안하기도 함 |
| 고차원 문제 | 피처 100개면 LLM 쿼리 1,000회 필요 |
| GPT-3.5 의존 | LLaMA-8B는 성능 크게 떨어짐 |

### 우리 프로젝트에 주는 것

- Claim 1과 구조가 가장 가깝다. "훈련 없이 LLM이 도메인을 알고 있는가"를 직접 검증하는 방법론
- Qwen2.5-14B로 우리가 실험할 때, 모델 크기가 작으면 GPT-3.5 대비 성능이 크게 떨어질 수 있음 → 현실적 기대치 조정 필요
- 호텔 예약은 LLM이 이미 아는 도메인(Cultivars처럼 특수하지 않음) → 성능 기대 근거

## 004. SHAP + LLM (arXiv 2512.00163, 2024년 12월)
**Measuring What LLMs Think They Do: SHAP Faithfulness and Deployability on Financial Tabular Classification**

### 왜 이 논문이 나왔는가

LLM이 테이블을 분류할 때 "실제로 어떤 피처를 보고 있는가"를 아무도 모른다. 금융처럼 규제가 엄격한 영역에서는 이게 치명적이다. 저자들은 두 가지를 비교한다: LLM이 자기 결정을 설명하는 것 vs SHAP이 LLM 행동을 외부에서 측정하는 것.

### 핵심 개념: SHAP Faithfulness

SHAP으로 "LLM이 실제로 어떤 피처에 반응하는가"를 측정하고, LLM이 스스로 설명하는 것과 비교한다.

```
[측정 방식]
LLM 자체 설명: "이 피처가 예측에 긍정/중립/부정 영향?"
                → LLM이 답변
SHAP 측정:     각 피처를 제거했을 때 예측이 얼마나 바뀌는가
                → 실제 행동 측정

[비교]
두 결과가 일치하면 faithful, 불일치하면 unfaithful
```

### 실험 설계

- 금융 데이터셋 3개: 파산 예측, 대출 상환, 증권사 면허
- LLM 4종: Gemma-2-9B, Llama-3.2-3B, Qwen-2.5-7B, Mistral-7B
- 평가: PR-AUC (불균형 데이터라 ROC-AUC 대신)

### 핵심 결과

**LLM이 자기 결정을 설명하는 능력:**
```
최고 성능 Gemma:  57.2% 정확도 (이유 포함 시)
Qwen:             29.4%
기저율(무작위):   33%
```

**LLM SHAP vs LightGBM SHAP 피처 순위 일치도 (Kendall τ):**
```
파산 예측: 0.011  (거의 무관)
대출 상환: 0.148
면허 미갱신: -0.186
```

→ LLM이 보는 피처와 ML이 보는 피처가 거의 다르다.

**이유:** LLM은 피처 이름의 어휘 편향에 걸린다. "현금"="좋음", "부채"="나쁨"처럼 단어 의미로 판단하고, 실제 데이터 패턴은 무시한다.

**분류 성능 (PR-AUC Lift):**
- 파산: 1.54× (기저율 대비), 대출: 1.09×, 면허: 1.38×
- 신호는 있지만 약함. 실용화하려면 few-shot 필요.

### 우리 프로젝트에 주는 것

이 논문은 경고다.

| 경고 | 우리 대응 |
|---|---|
| LLM이 자기 결정을 설명 못 함 | Claim 1은 성능 측정만 한다. 설명 요구하지 않는다 |
| LLM과 ML이 보는 피처가 다름 | 오히려 좋다. 다른 패턴 → 보완재 가능성 |
| 어휘 편향 위험 | 피처명을 직관적으로 유지해야 함 (`lead_time`보다 `Days before check-in`) |

**그리고 이 논문이 우리 방어 논리를 도리어 도와준다:**
LLM SHAP과 ML SHAP이 다르다면 → LLM은 ML이 보지 못하는 다른 패턴을 본다 → 두 방법이 일치할 때는 더 강한 신호, 불일치할 때는 보완 정보.

## 005. AgentSociety (arXiv 2502.08691, 2025년 2월)
**Large-Scale Simulation of LLM-Driven Generative Agents Advances Understanding of Human Behaviors and Society**

### 왜 이 논문이 나왔는가

기존 ABM은 수치 벡터, 방정식, 규칙으로 인간을 모델링한다. 의견을 0-1 스칼라로, 감정을 확률로 표현한다. 인간이 실제로 어떻게 결정하는지는 담지 못한다. George Herbert Mead의 말을 빌려: "자아는 사회적 경험에서 생성된다" — ABM은 그 경험 과정을 재현하지 못한다. LLM은 자연어로 추론하고 맥락을 이해한다. 이걸 에이전트로 쓰면?

### 핵심 설계: Emotions × Needs × Cognition 3층

**Emotion 레이어 (Shvo et al. 프레임워크)**
- 슬픔, 기쁨, 두려움, 혐오, 분노, 놀람 — 6개 기본 감정을 0-10으로 수치화
- 다른 에이전트와의 상호작용마다 업데이트
- 이후 행동 결정과 메시지 톤에 영향

**Needs 레이어 (Maslow + Theory of Planned Behavior)**
- 생존(수면, 식사) → 사회(만남, 대화) → 자아실현 순 위계
- 각 욕구 0-100 만족도로 추적
- 만족도 낮은 욕구가 다음 행동 목표를 결정
- 비, 우울증, 외부 충격으로 욕구 변화

**Cognition 레이어**
- 행동 실행 후 "나는 지금 뭘 했는가"를 문장으로 기술
- 이것이 Attitude(0-10 스케일) 업데이트 트리거
- 이전 상호작용 기억과 결합해 다음 판단에 영향

**피드백 루프:**
```
행동 실행 → Event 기록 → Emotion·Cognition이 분석
→ Needs 재조정 → 다음 행동 결정 → (반복)
```

### 사회 환경: 3공간

- **도시 공간:** OpenStreetMap 기반 실제 도로망, POI(카페·식당·직장), 중력 모델로 이동 목적지 결정
- **사회 공간:** 가족·친구·동료 관계 0-100 강도, 과거 대화 이력 반영
- **경제 공간:** 기업·개인·정부·은행 4주체, GDP·고용률·소비 지표 추적

### 4가지 검증 실험

| 실험 | 설계 | 검증 방식 |
|---|---|---|
| 양극화 | 다양한 정치 의견으로 초기화 → 자유 대화 | 실제 온라인 커뮤니티 양극화 패턴과 비교 |
| 선동 메시지 확산 | 한 에이전트에서 메시지 주입 → 전파 추적 | 실제 소셜 미디어 감염률과 비교 |
| 기본소득 | 정부가 매달 지급 → 경제·사회 변화 추적 | 핀란드·캐나다 실제 파일럿 결과와 비교 |
| 허리케인 충격 | 특정 지역 인프라 손상 주입 → 여파 추적 | 허리케인 Harvey 실제 데이터와 비교 |

10,000명 에이전트, 5백만 건 상호작용.

### 저자 인정 한계

- 경제 공간 단순화: 노동시장 협상, 실업 프로세스 미모델링
- 온라인 상호작용만: 오프라인 대면, 비언어 소통 없음
- LLM 환각(hallucination): 빈도 높아질수록 오류 누적
- TCP 포트 제약으로 10k 이상 확장 어려움

### 우리 프로젝트에 주는 것

- 3층 심리 구조의 원출처. 현재 우리는 이 구조를 직접 쓰지 않기로 했지만, "왜 안 쓰는가"를 설명할 때 이 논문을 알고 있어야 함
- 4가지 사회 현상 재현 = "방법론이 다른 도메인에서 작동했다"는 선례
- 규모(10k, 5M 상호작용) = 우리 20k가 충분히 의미 있음을 지지

## 006. LLM Multi-Agent Consumer Behavior (arXiv 2510.18155, 2025년 10월)
**LLM-Based Multi-Agent System for Simulating and Analyzing Marketing and Consumer Behavior**

### 왜 이 논문이 나왔는가

기업은 신제품·할인·캠페인을 출시하기 전에 효과를 알고 싶다. 설문, 포커스그룹, A/B테스트는 비싸고 느리다. LLM 에이전트로 미리 돌려보면 어떨까?

### 에이전트 설계

**11명 이질적 에이전트 (22-35세, 직업·소득 다양)**

**메모리 3단계:**
1. Ingestion: 행동마다 EVENT/REFLECTION/CONVERSATION/PURCHASE 태깅 저장
2. Retrieval: 시간 감쇠 + 관계 근접성 필터로 관련 기억만 꺼냄
3. Integration: 꺼낸 기억을 프롬프트에 포함 → LLM이 JSON으로 답변

**행동 파이프라인:**
```
내부 필요(Needs) → LLM 프롬프트 → JSON 응답
{"time": 12, "action": "eat", "target": "Local Diner", "reason": "..."}
→ 실행 → 메모리 로깅 → (반복)
```

**Needs Triad:** Grocery(식료품) / Energy(체력) / Money(돈) — 각각 소비되고 보충됨

### 실험 시나리오

중앙에 Fried Chicken Shop, 왼쪽에 Coffee Shop, 오른쪽에 Local Diner를 배치하고 에이전트들이 하루를 살아간다. 3일차에 Fried Chicken Shop이 20% 할인을 시작한다.

### 구체적 수치 결과

| 지표 | 수치 |
|---|---|
| 2일차 매출 (기준) | $100.60 |
| 3일차 매출 (할인 시작) | $152.11 (+51%) |
| Local Diner 영향 | 점유율 62% → 48% (-14%p) |
| Fried Chicken 점유율 | 30% → 41% (+11%p) |
| 할인 효과 지속 | 2-3일 후 변동성 증가 |
| 시장 총 규모 변화 | 없음 (대체 효과만 발생) |

### 창발 현상 — 프로그래밍 없이 자발적으로 나타난 것

- **습관 형성:** Kevin, Rebecca가 Fried Chicken Shop을 연속 방문
- **그룹 형성:** Lisa가 친구들에게 커피 제안 → 4명이 자발적으로 합류
- **사회적 조율:** 공통 장소 선택이 메모리+대화에서 자연스럽게 수렴
- **문헌 일치:** 대체 효과(substitution effect) — 시장 총량 불변, 점유율만 이동

### 저자 인정 한계

| 한계 | 내용 |
|---|---|
| 할루시네이션 | "new bistro near Oak View Condos" (존재하지 않는 장소) 제안 |
| 연령 편향 | 7세 아동이 성인처럼 커피 주문, 노인이 건강 걱정 안 함 |
| 에너지 고갈 | 에너지 0 → 기능 불능 상태. 임계값 강제 복구 로직 필요 |
| 모델 의존 | Llama2는 동일 프롬프트에서 결과 불안정 |

### 우리 프로젝트에 주는 것

- Flexi 할인율 실험의 **직접 선례**. 할인율 × 에이전트 반응 구조가 우리 Claim 2와 동일
- **대체 효과 재현** = LLM 에이전트가 경제학 이론에 맞는 방향으로 반응함
- 11명으로 창발이 나왔다면 20,000명에서는 훨씬 풍부한 세그먼트 패턴이 나올 것
- 연령 편향 한계 → 우리는 국적·채널·lead_time 기반 세그먼트이므로 이 한계 해당 없음

## 007. MALLES (arXiv 2603.17694, 2026년 3월)
**Multi-Agent LLMs-based Economic Sandbox with Consumer Preference Alignment**  
Yusen Wu, Yiran Liu, Xiaotie Deng

### 왜 이 논문이 나왔는가

기존 경제 시뮬레이션은 에이전트 행동을 수식과 규칙으로 고정한다. "소득이 높으면 더 산다"는 식이다. 하지만 실제 소비자 선호는 카테고리마다 다르고, 데이터 카테고리별로 거래 기록이 부족해서 학습이 안 된다. MALLES는 두 문제를 동시에 푼다: LLM에 실제 거래 데이터로 선호를 학습시키고(post-training), 여러 카테고리의 지식을 공유해서 데이터 희소성 문제를 넘는다.

### 핵심 파이프라인

```
[실제 거래 데이터]
  119,252명 고객 × 3,361 상품 카테고리

      ↓ (1) Post-training
  LLM이 가격 탄력성·할인 민감도·카테고리 간 선호 이동을 학습
  (cross-category transfer로 데이터 희소성 극복)

      ↓ (2) Mean-Field Mechanism
  에이전트 × 상품 시장 상호작용 안정화
  이동평균 μₜ로 마켓 반응을 통합 → 분산 감소

      ↓ (3) Multi-Agent Discussion
  딜러·서비스·제조사 에이전트 3역할이 다회전 토론
  → 도메인별 인사이트 합산 → 구매 결정 JSON 출력
```

**왜 Multi-Agent Discussion인가:** 단일 LLM 호출로는 경쟁 상황·판촉 전략·생산 제약을 동시에 처리하기 어렵다. 역할을 분리해서 각자 전문 분석을 하게 하면 더 풍부한 결정이 나온다.

### 실험 설계

- 평가: 119,252건 중 1,000건 샘플로 Product Selection Accuracy, Quantity Error 측정
- 비교 베이스라인: EconAgent, ABIDES-Economist, FinCon

### 핵심 결과

| 지표 | MALLES (enhanced) | MALLES (base) | FinCon |
|---|---|---|---|
| Product Selection Accuracy | **77.5%** | 70% | — |
| Cross-category hit rate | **0.60** | 0.25 (single-cat) | — |
| Quantity Error | 더 안정적 | — | 1.325 |

카테고리 간 전이 학습이 핵심이다. 단일 카테고리 학습(0.25)에서 cross-category(0.60)로 2.4배 향상. **데이터가 적은 카테고리에서도 다른 카테고리 지식을 빌려 쓴다.**

### 저자 인정 한계

| 한계 | 내용 |
|---|---|
| 멀티모달 미개발 | 시각·텍스트·수치 융합이 부족 |
| 마이크로-마크로 결합 | 개별 에이전트 결정 ↔ 시장 전체 동학 연계 약함 |
| 윤리 문제 | 개인화 예측이 조작적 마케팅에 악용될 수 있음 |
| 텍스트 편향 | 수치 신호보다 텍스트 설명에 더 민감하게 반응 |

### 우리 프로젝트에 주는 것

구조적으로 가장 유사한 논문이다.

```
MALLES:  실제 거래 데이터 → Post-training → 소비자 선호 추출 → 시뮬레이션
우리:    실제 예약 데이터 → 피처 직렬화 → 아크타입 도출  → Flexi 시뮬레이션
```

차이는 우리가 post-training이 아니라 **프롬프트 수준**에서 접근한다는 것. MALLES는 LLM을 훈련시키고, 우리는 프롬프트로 컨텍스트를 제공한다. 우리 방식이 더 단순하고 재현 가능하다는 장점이 있다.

## 008. WTP Hotel (arXiv 2602.09802, 2026년 2월)
**Would a Large Language Model Pay Extra for a View? Inferring Willingness to Pay from Subjective Choices**  
Manon Reusens, Sofie Goethals, Toon Calders, David Martens

### 왜 이 논문이 나왔는가

LLM이 소비자 시뮬레이션에 쓰일 수 있는지를 따지려면, LLM이 실제로 "가격 대비 가치 판단"을 할 수 있는지 측정해야 한다. 호텔 룸 선택은 딱 맞는 테스트베드다: 뷰, 층수, 취소 정책, 가격이 충돌하는 상황에서 LLM이 얼마를 낼 의향이 있는가? 이걸 Multinomial Logit으로 WTP(Willingness To Pay)로 환산한다.

### 실험 설계

```
480개 가능한 호텔 룸 설정에서 쌍을 뽑아 240개 딜레마 생성
각 딜레마: "A 방 vs B 방 중 어느 것을 선택하겠습니까?"

[속성 6개]
  뷰: 도시 vs 항구
  층수: 10층 / 18층 / 26층
  호텔 클럽 이용권: 있음 / 없음
  미니바: 음료+스낵 / 확장 선택지
  스마트폰 제공: 있음 / 없음
  취소 정책: 환불 불가 / 환불 가능
  1박 가격: HK$1600~3200

[페르소나]
  비즈니스 여행자: 회사 부담, 편의 우선
  학생 여행자: 예산 제한, 경제성 우선

[LLM 3종]
  Llama 3.3 70B / GPT-4o / Gemini-3-Pro
  (소형 모델은 순서 편향 심해서 제외)
```

인간 벤치마크: 2015년 연구에서 얻은 홍콩 여행객의 실제 WTP 값 (물가 보정).

### 핵심 WTP 결과

| 속성 | Llama 70B | GPT-4o | Gemini-3-Pro | 인간 벤치마크 |
|---|---|---|---|---|
| 뷰 (항구) | HK$511 | HK$116 | HK$241 | **HK$771** |
| 클럽 이용권 | HK$1,874 | HK$1,349 | HK$721 | **HK$437** |
| 취소 정책 (환불) | HK$1,616 | HK$712 | HK$378 | **HK$122** |

**패턴이 명확하다:**
- 뷰: LLM이 일관되게 **과소평가** (인간 대비 15~67% 수준)
- 클럽 이용권: LLM이 일관되게 **과대평가** (인간의 1.6~4.3배)
- 취소 정책: LLM이 극단적으로 **과대평가** (인간의 3.1~13.2배) ← **우리에게 중요**

### 시스템적 편향 원인 분석

1. **설명 길이 효과**: 클럽 이용권이 긴 설명(수영장, 피트니스, 라운지...)을 가지면 LLM이 더 높은 가치를 부여 → 설명이 길수록 WTP 상승
2. **페르소나 극단화**: 학생 페르소나를 준 Gemini는 최저가만 선택 → 경제 모델링 자체가 불가능해짐 ("perfect separation" 문제)
3. **컨디셔닝 의존**: 이전에 저렴한 선택 3개를 제시하면 WTP가 인간 벤치마크에 가장 근접 → LLM이 맥락에 크게 흔들린다는 증거

### 저자 인정 한계

- 인간 벤치마크가 2015년 기준 → 스마트폰 같은 속성은 선호가 크게 변했을 것
- 단일 도시(홍콩) 데이터 → 문화적 일반화 불가

### 우리 프로젝트에 주는 것

**핵심 기여:** LLM이 호텔 도메인에서 가격 + 취소 정책에 반응하는 의사결정을 실제로 한다는 직접 증거.

```
WTP Hotel 실험 구조      우리 Claim 2 구조
───────────────────────   ────────────────────────
속성 A vs 속성 B 선택  ≈  Flexi 수락 vs 거절 선택
취소 정책 WTP 측정      ≈  취소 조건 변경에 대한 수락률
페르소나별 WTP 차이     ≈  아크타입별 수락률 분산
```

**경고도 있다:** 취소 정책 WTP가 인간 대비 3~13배 과대평가됐다. Flexi 시뮬레이션에서 LLM이 취소 조건 변경을 지나치게 중요하게 볼 수 있다는 뜻이다. 우리가 "방향성 탐색"이라고 포지셔닝하는 이유가 여기에도 있다 — 절댓값이 아니라 세그먼트 간 상대적 차이를 본다.

## 009. Can LLM Simulate Multi-Turn? (arXiv 2503.20749, 2025년 3월)
**Can LLM Agents Simulate Multi-Turn Human Behavior? Evidence from Real Online Customer Behavior Data**  
Yuxuan Lu, Jing Huang 외 | Meta × UMass

### 왜 이 논문이 나왔는가

기존 LLM 에이전트 평가는 "그럴듯해 보이는가"를 연구자 주관으로 판단한다. 이 논문은 다르다: 실제 쇼핑 행동 데이터를 가져다가 LLM이 같은 상황에서 같은 행동을 하는지 **수치로** 측정한다. 단순하지만 이전 연구들이 안 한 일이다.

### 실험 설계

```
데이터: 31,865개 실제 온라인 쇼핑 세션
        230,965개 사용자 행동 (검색·클릭·카트·구매·이탈)

모델:
  프롬프트 전용: DeepSeek-R1, Llama, Claude
  파인튜닝: Qwen2.5-7B (실제 세션 + 합성 추론 트레이스로 훈련)

평가:
  1. Action Accuracy: LLM이 생성한 다음 행동이 실제와 일치하는가
  2. Purchase F1: 세션 결과(구매/이탈)를 올바로 예측하는가
```

### 핵심 결과

| 방식 | Action Accuracy | Purchase F1 |
|---|---|---|
| 프롬프트 전용 LLM | **11.86%** | — |
| 파인튜닝 Qwen2.5-7B | **17.26%** | **33.86%** |
| 파인튜닝 향상폭 | +5.4%p | +13.85%p |

**프롬프트만으로는 개별 행동 정확도 12%가 나온다.** 인간이 실제로 클릭하고 이탈하는 세부 순서를 LLM이 재현하지 못한다.

### 이 논문이 경고하는 것

"LLM 에이전트가 개별 행동 수준에서 인간을 재현하지 못한다." 12%는 무작위보다도 낮은 수준이다.

### 우리 프로젝트에 주는 것 — 오히려 방어가 된다

이 논문이 비판하는 것은 **개별 행동 순서 재현**이다. 우리 Claim 2는 그걸 하지 않는다.

```
이 논문이 측정한 것:
  "사용자가 A → B → C → 구매를 했는데, LLM도 A → B → C → 구매를 하는가?"
  → 개별 다회전 행동 시퀀스 정확도

우리가 측정하는 것:
  "10% 할인 오퍼에 PRT × OTA 세그먼트 수락률이 몇 %인가?"
  → 세그먼트 수준 집단 패턴
```

개별 행동 재현은 못 하더라도, 세그먼트 집단 반응의 방향성(할인↑ → 수락↑)은 나올 수 있다. 이 논문은 우리 포지셔닝을 강화한다: "개별 예측이 아니라 방향성 탐색"이 올바른 프레임임을 이 비판 논문이 역설적으로 증명한다.

## 010. "Let It Go or Control It All?" (System Dynamics Review, 2025년 7월)
**The Dilemma of Prompt Engineering in Generative Agent-Based Models**  
Zewei Li, Qi Wu

### 왜 이 논문이 나왔는가

LLM 기반 ABM이 폭발적으로 늘면서, 연구자마다 프롬프트 설계를 감각으로 한다. "어디까지 지정해야 하는가, 어디까지 LLM이 자율적으로 판단하게 두어야 하는가" — 이 질문을 체계적으로 분석한 논문이 없었다. Li & Wu는 22개 논문을 분석해서 이 딜레마를 문서화한다.

### 분석 프레임워크: 4개 컴포넌트

```
에이전트 = [Profile] + [Memory] + [Planning] + [Action]

Profile:  에이전트 정체성 — 나이·직업·성격 명시 범위
Memory:   과거 경험 저장/검색 방식 — 무엇을 기억하게 할 것인가
Planning: 행동 계획 구조 — 단계를 강제할 것인가, 자유롭게 둘 것인가
Action:   실행 명령 형식 — JSON 강제 vs 자연어 출력
```

### 핵심 발견: 과잉 통제(Over-Control) 패턴

22개 논문 중 다수가 **프롬프트로 결과를 미리 결정**하는 패턴에 빠져 있다.

```
[과잉 통제 예시]
  "다음 4단계를 순서대로 수행하라:
   1. 이 여행에 대한 확신도를 0-10으로 평가하라
   2. 가격 민감도를 낮음/중간/높음으로 분류하라
   3. 할인이 충분한지 판단하라
   4. 최종 결정을 내려라"

[문제]
  에이전트는 실제로 추론하지 않는다.
  프롬프트가 시킨 단계를 채워 넣는다.
  결과가 프롬프트 설계자의 기대를 따라간다.
  창발(emergence)이 사라진다.
```

**프롬프트 연속선:**
```
← 완전 자율                                    완전 통제 →
"이 상황에서 어떻게 할 것인가?"  vs  "1단계: ... 2단계: ... 3단계: ..."
   창발적 행동 가능                  결과가 프롬프트에 내포됨
```

### 권장 방향

- Profile: 정체성은 제공하되 심리 수치를 직접 주입하지 말 것
- Planning: 단계 강제 대신 결정 맥락(상황, 제약)만 제공
- Action: 출력 형식은 고정하되 추론 과정은 자유롭게
- Memory: 관련 과거 정보를 주되 해석은 LLM이 하게

### 우리 프로젝트에 주는 것

design_13의 **"고정 원칙"이 이 논문을 그대로 구현한 것**이다.

```
이 논문의 권장      design_13 반영
───────────────      ─────────────────────────────
심리 수치 직접 주입 금지   → 심리 레이어 명시 금지 원칙
단계 강제 금지             → D variant (4단계 강제) 폐기
해석 언어 금지             → "suggesting uncertain plans" 같은 표현 금지
출력 형식 고정             → 모든 variant에서 OUTPUT 블록 고정
```

"왜 우리가 4단계 추론 강제를 버렸는가"라는 질문에 이 논문이 이론적 근거를 준다.

## 011. Persona Policies PPol (arXiv 2605.12894, 2026년 5월)
**Beyond Cooperative Simulators: Generating Realistic User Personas for Robust Evaluation of LLM Agents**  
Harshita Chopra, Kshitish Ghate, Aylin Caliskan, Tadayoshi Kohno, Chirag Shah, Natasha Jaques

### 왜 이 논문이 나왔는가

현재 LLM 에이전트 평가는 협조적이고 균질한 사용자 시뮬레이터를 쓴다. 실제 사용자는 다르다: 짧게 대답하거나, 의심하거나, 화를 내거나, 예상 밖의 방식으로 행동한다. 이런 다양성이 없으면 에이전트 평가가 지나치게 낙관적이다. 하지만 현실 데이터 수집은 비싸다. 해결책: 진화 알고리즘으로 다양한 페르소나를 자동 생성한다.

### 핵심 아이디어: MAP-Elites + LLM 진화

```
[MAP-Elites 알고리즘]
  다목적 진화 탐색 — 행동 다양성 × 현실성 두 축을 동시에 최대화

[과정]
  1. LLM이 초기 페르소나 집합 생성
  2. 각 페르소나로 에이전트와 대화 시뮬레이션
  3. fitness 점수 계산:
     - 현실성: 실제 인간과 얼마나 비슷한가
     - 다양성: 기존 페르소나 풀과 얼마나 다른가
  4. 고점수 페르소나를 교차·변이 → 새 페르소나 생성
  5. 반복 → 자연적으로 발견된 행동 축 형성
```

**자동으로 발견된 행동 축 예시:**
- terseness (짧게 대답하는 경향)
- skepticism (의심하는 경향)
- frustration (불만을 표출하는 경향)
- escalation (요구가 점점 강해지는 경향)

이 축들은 사람이 미리 정한 게 아니다. MAP-Elites가 데이터에서 찾아낸다.

**플러그앤플레이:** 기존 시뮬레이터 프롬프트 위에 레이어로 얹는다. 시뮬레이터 자체를 수정하지 않는다.

### 실험 설계

- 도메인: 소매 + 항공사 고객 서비스
- 평가: fitness 점수, 인간 주석자 평가, 에이전트 강건성 테스트

### 핵심 결과

| 지표 | 수치 |
|---|---|
| fitness 향상폭 | **33~62% 절대 향상** (베이스라인 대비) |
| 인간 현실성 평가 | **80.4%** (주석자가 인간으로 분류) |
| 에이전트 강건성 | **+17% 상대 향상** (어려운 행동에서 성공률) |

### 저자 인정 한계

- 순수 시뮬레이션 기반 훈련 에이전트는 미보인 행동 패턴에 취약할 수 있음
- 특정 도메인에서의 검증이라 범용화 주의 필요

### 우리 프로젝트에 주는 것

PPol은 우리 design_13 AGENT 블록의 **자동화 미래 버전**이다.

```
우리 (Phase 1):           PPol:
  수동 variant A/B/C        자동 진화로 variant 생성
  인구통계 기반 페르소나     행동 축 기반 페르소나
  연구자가 설계              MAP-Elites가 탐색
```

Phase 1에서는 수동 실험으로 최적 AGENT variant를 찾고, Phase 2 이후에서 PPol 방식으로 자동화하는 로드맵이 자연스럽게 연결된다. 발표에서 "앞으로의 방향"으로 언급할 수 있는 선행 연구.

## 012. Sarstedt 2024 — Silicon Samples
**Using Large Language Models to Generate Silicon Samples in Consumer and Marketing Research**  
Marko Sarstedt et al. | *Psychology & Marketing*, 2024

### 왜 이 논문이 나왔는가

소비자 연구에서 인간 응답자를 LLM으로 대체하려는 시도가 늘고 있다. 저자들은 이게 언제 작동하고 언제 작동 안 하는지를 체계적으로 정리한다. 285개 "실리콘 샘플 vs 인간 샘플" 비교 데이터를 종합해서 가이드라인을 제시한다.

### 핵심 분석: 285개 비교의 결과

```
실리콘 샘플 ≈ 인간 샘플:   24.9% (약 71건)
부분 일치:                  9.8%
불일치:                    65.3% (약 186건)
```

10번 중 6.5번은 LLM 응답이 인간 응답과 다르다.

### 불일치 원인 분석

| 원인 | 설명 |
|---|---|
| 영어·서구 편향 | LLM 훈련 데이터가 영어권 Wikipedia·GitHub 중심 → 비서구 문화에서 더 부정확 |
| 개인 경험 결여 | LLM은 "평균적인 관점"을 답한다. 개인의 고유한 삶의 경험이 없음 |
| 사회적 바람직성 편향 | 도덕적으로 "좋은" 답변을 선호하는 경향 |
| 일관성 부재 | 동일 질문을 다시 하면 다른 답이 나오는 경우 있음 |
| 도메인 지식 한계 | 익숙하지 않은 제품 카테고리에서 신뢰도 급락 |

### 언제 쓸 수 있는가 (권장 용도)

```
[권장 — Upstream 탐색용]
  정성적 사전 테스트      ← 우리 포지션
  파일럿 연구
  설문 문항 초안 검토
  가설 방향 탐색

[주의 — 단독으로 쓰기 위험]
  메인 연구 응답자 대체
  인과관계 주장
  정량적 예측 근거
```

### 우리 프로젝트에 주는 것

이 논문은 가장 강력한 비판 선행 연구이면서, 동시에 가장 강력한 방어 근거다.

**비판으로 쓰면:** "실리콘 샘플의 65.3%는 인간과 불일치한다" → LLM 시뮬레이션은 한계가 크다.

**방어로 쓰면:** "권장 용도가 파일럿 탐색이다" → 우리 Claim 2가 정확히 그 용도다.

```
Sarstedt의 권장 범위:  파일럿 탐색, 방향성 확인
우리 포지셔닝:         "할인율 파라미터 방향성을 사전 탐색하는 도구"
                        → 권장 범위 내
```

발표에서 이 논문을 먼저 소개하고 "우리는 이 비판을 알고 있고, 권장 범위 내에서 사용한다"고 하면 방어력이 생긴다.

## 013. Critical Review LLM ABM (arXiv 2504.03274, 2025년 4월)
**Do Large Language Models Solve the Problems of Agent-Based Modeling? A Critical Review of Generative Social Simulations**  
Maik Larooij, Petter Törnberg

### 왜 이 논문이 나왔는가

LLM이 ABM에 통합되면서 "이제 사회 시뮬레이션이 해결된다"는 낙관론이 생겼다. Larooij & Törnberg는 이 낙관론이 과연 근거가 있는지를 따진다. 35개 논문을 검토하고, ABM의 기존 문제를 LLM이 해결했는지, 아니면 오히려 악화시켰는지를 점검한다.

### 35개 논문 검토 결과

**검증 방식 분포:**
```
주관적 검증만 사용:       62.9% (22/35편)
일부라도 주관적:          42.9% (15/35편)
단일 실험 실행:           대다수
감도 분석 실시:           소수
```

"모델이 그럴듯해 보이는가"를 연구자가 눈으로 판단 → 이것이 35편 중 63%의 검증 방식이다.

### 3가지 핵심 비판

**1. 블랙박스 불투명성**
LLM은 수십억 개 파라미터. 왜 특정 출력이 나왔는지 알 수 없다. ABM의 본래 강점은 인과 메커니즘을 명시적으로 추적하는 것인데, LLM이 들어오면 그게 불가능해진다.

**2. 영점 모델 캘리브레이션**
35편 중 거의 전부가 파인튜닝 없이 제로샷 모델을 쓴다. "믿을 만해 보이게" 프롬프트를 조정하는 것으로 캘리브레이션을 대체한다. 실제 개인 행동 데이터와의 정렬은 없다.

**3. 검증 불충분**
단일 실험 실행으로 결론을 내린다. 생성형 ABM은 내재적으로 확률적인데, 1회 실행의 결과를 인과 주장의 근거로 쓴다. 감도 분석도 없다.

### 저자의 결론

LLM은 ABM의 오래된 문제(검증 어려움, 블랙박스, 캘리브레이션 불가)를 해결하지 못한다. 오히려 악화시킨다. 진지한 사회 과학 연구 도구가 되려면:
- 실제 개인 데이터로 엄격한 캘리브레이션, 또는
- 단순하고 일반화 가능한 창발 현상에 집중

두 경로 중 하나를 가야 한다.

### 우리 프로젝트에 주는 것

세 비판 모두에 대응 방안이 있다.

| 비판 | 우리 대응 |
|---|---|
| 주관적 검증만 함 | 세그먼트 간 수락률 분산이라는 수치 지표 사용 |
| 단일 실험 실행 | 20,000건 × 할인율 3단계 반복 실험 |
| 캘리브레이션 없음 | Claim 1이 같은 데이터셋에서 LLM 도메인 이해를 수치로 검증 |

이 논문을 알고 있다는 것 자체가 방어다. "우리는 이 비판들을 읽었고, 우리 실험 설계에 반영했습니다"는 발표에서 신뢰도를 높인다.

## 014. LLM economicus (arXiv 2408.02784, 2024년 8월)
**LLM economicus? Mapping the Behavioral Biases of LLMs via Utility Theory**  
Jillian Ross, Yoon Kim, Andrew W. Lo | MIT

### 왜 이 논문이 나왔는가

"LLM이 행동경제학을 학습했을 것이다"라는 가정이 많은 연구에서 그냥 쓰인다. MIT 팀은 이걸 실제로 측정한다: LLM이 경제 게임에서 내리는 결정이 인간의 행동 편향 패턴과 일치하는지를 효용 이론(Utility Theory)으로 정량화한다.

### 실험 설계

```
모델 8종: GPT-3.5T / GPT-4 / GPT-4T / Claude 2.1 / Gemini / LLaMA 7B·13B·70B / Mistral 7B

편향 3종류:
  1. 불평등 회피 (Inequity Aversion) — Ultimatum Game
     Fehr-Schmidt 효용함수, 질투 파라미터 α & 죄책감 파라미터 β 추정

  2. 위험·손실 회피 (Risk & Loss Aversion) — 도박 게임
     Prospect Theory, 손실 회피 파라미터 λ 추정

  3. 시간 할인 (Time Discounting) — 지연 보상 게임
     쌍곡형 할인 모델, 할인율 k 추정

방법: 각 설정마다 N=100회 반복 → 분포로 파라미터 추정
```

**능력 테스트 통과 모델:** GPT-4, GPT-4T만 위험 게임에서 통과. LLaMA·Mistral 대부분 실패.

### 핵심 결과

**불평등 회피:**
```
인간:    α ≈ 0.5~1.0 (불공정 제안 거절)
LLM:    α가 훨씬 낮음 → 불공정 제안도 수락 (더 합리적, 덜 질투)
        β가 높음 → 제안할 때 더 관대 (지나친 이타성)
```

**손실 회피 — 모델 간 불일치:**
```
GPT-4:    손실에 위험 회피적 (인간과 유사)
GPT-4T:   손실에 위험 추구적 (인간과 반대)
→ 동일 계열 모델인데 정반대 패턴
```

**시간 할인:**
```
모든 LLM: 인간보다 훨씬 강한 현재 선호
          1개월 후 돈 > 지금 돈을 일관되게 선택 안 함
          50년 후도 마찬가지 — 경제적으로 비합리적
```

**프롬프트 개입 효과:**
| 방법 | 효과 |
|---|---|
| 직접 지시 ("위험 회피하게 행동해라") | 효과 없음 |
| Zero-shot CoT | 효과 없음 |
| One-shot 예시 | GPT-4에서 효과 있음 |
| Two-shot 예시 | 역효과 (이득·손실 혼동) |
| 역할 페르소나 (노인/청소년) | 소폭 변화, 불안정 |

### 저자 인정 한계

- 훈련 데이터 암기 가능성 — 경제 게임 문제를 이미 학습했을 수 있음
- 실험실 설정 — 실제 경제 상황과 다름
- 프롬프트 형식에 민감 — 표현 방식에 따라 결과 변동

### 우리 프로젝트에 주는 것

이 논문은 "LLM이 행동경제학을 학습했다"는 가정에 직접 반론한다. **그래서 우리 방어 논리의 출발점이 된다.**

```
[이 논문이 보여준 것]
  LLM의 경제적 행동 편향은:
    - 모델마다 다르다 (GPT-4 vs GPT-4T가 손실 회피에서 정반대)
    - 인간과 다르다 (시간 할인이 극단적)
    - 프롬프트로 통제가 어렵다

[우리 Claim 1이 대응하는 방식]
  "LLM이 행동경제학을 이해하는지 이론으로 논쟁하지 않는다.
   훈련 없이 테스트셋에서 PR-AUC X.XX가 나왔다.
   호텔 취소 행동을 이해하는지는 숫자가 답한다."
```

Claim 1이 이 논문의 비판을 우회하는 구조다. 이론 가정 없이 직접 측정으로 대체한다.

추가로: 이 논문이 보여준 모델 간 불일치는, 우리가 Qwen2.5-14B 단일 모델을 쓸 때 다른 모델 결과와 다를 수 있다는 주의 사항으로도 활용된다. **모델 선택이 중요하다는 근거.**
