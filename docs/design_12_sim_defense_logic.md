## 핵심 주장 구조

복잡한 이론 체계를 걷어낸다. 방어해야 할 것은 두 개뿐이다.

```
주장 1: LLM은 호텔 예약 취소 행동을 이미 이해한다
           ↓ 증명 방법
        훈련 없이 테스트셋에서 예측 성능이 나온다

주장 2: 호텔 수집 가능한 데이터로 게스트 아크타입을 만들 수 있고
        그 아크타입이 Flexi 시뮬레이션에서 효용이 있다
           ↓ 증명 방법
        아크타입 기반 시뮬레이션 vs 기반 없는 시뮬레이션 비교
```

주장 1이 성립하면 "LLM이 행동경제학을 아는가"는 더 이상 질문이 아니다.  
데이터가 직접 답한다.

## 주장 1 — LLM의 제로샷 취소 예측

### 검증 파이프라인

예약 데이터를 자연어로 전처리해서 LLM에 그대로 던진다.

```python
prompt = """
A hotel guest made a booking with the following details:
- Country: {country}
- Booking channel: {market_segment}
- Days before check-in: {lead_time}
- Special requests: {total_of_special_requests}
- Parking required: {required_car_parking_spaces}
- Average daily rate: €{adr}
- Previous cancellations: {previous_cancellations}

What is the probability (0.0 to 1.0) that this booking will be cancelled?
Answer with a single number only.
"""
```

- 입력: 테스트셋 (2017-01 ~ 2017-08, 40,687건)
- 모델: Qwen2.5-14B (로컬, A5000 × 2)
- 출력: 취소 확률 0.0 ~ 1.0
- 평가: PR-AUC, F1@0.5

### "괜찮은 성능"의 기준

우리 LGBM 베이스라인과 비교한다.

| 모델 | PR-AUC | 비고 |
|---|---|---|
| Dummy | ~0.37 | 취소율 = 기저선 |
| LR Baseline | ~0.75 | Week 2 결과 |
| LGBM (우리 모델) | ~0.85+ | Week 3 결과 |
| **LLM Zero-shot** | **측정 예정** | 훈련 없음 |

LLM이 Dummy를 유의미하게 넘으면 **"LLM이 이 도메인을 이해한다"는 증거**가 된다.  
LR 수준에 근접하면 게임오버다.

### 이 실험이 해결하는 것

기존에 가정으로만 주장하던 것을:

> "LLM이 행동경제학을 학습했을 것이다"

데이터로 대체한다:

> "훈련 없이 테스트셋에서 PR-AUC X.XX가 나왔다"

이론 논쟁이 사라지고 숫자가 말한다.

## 주장 2 — 게스트 아크타입과 그 효용

### 아크타입이란

호텔이 실제로 수집 가능한 예약 정보로 만들어지는 **반복 등장하는 고객 유형**.  
우리가 임의로 설계하는 게 아니라 데이터에서 도출한다.

```
[우리 데이터 2년치]
    ↓ SHAP Top 피처 기반 클러스터링 (또는 LLM 분류)
    ↓
아크타입 예시:
  Type A: 포르투갈 직접 예약 / lead_time 단기 / 특별 요청 없음 → 취소율 낮음
  Type B: 독일 OTA 예약 / lead_time 180일+ / 특별 요청 0 → 취소율 높음
  Type C: 영국 그룹 예약 / 주차 필요 / 특별 요청 다수 → 취소율 낮음
  ...
```

### 효용 증명 방법

아크타입이 있을 때와 없을 때 시뮬레이션 결과를 비교한다.

| 조건 | 시뮬레이션 방식 |
|---|---|
| 베이스라인 | 아크타입 없이 취소 확률 + 피처만 제공 |
| 아크타입 적용 | 해당 아크타입 설명 + 취소 확률 + 피처 제공 |

**측정 지표**: Flexi 수락률의 세그먼트간 분산  
아크타입이 없으면 모두 비슷한 수락률 → 아크타입이 있으면 세그먼트별 차이가 뚜렷해짐  
차이가 생기는 것 자체가 아크타입이 정보를 추가하고 있다는 증거.

### 호텔이 쓸 수 있는 구조

```
[Phase 1: 발표 시점]
  우리 2년치 데이터 → 아크타입 도출
  → Flexi 시뮬레이션 실행

[Phase 2: 호텔 도입 후]
  실제 운영 데이터 수집
  → 아크타입 calibration (이 호텔 고객에 맞게 조정)

[Phase 3: 장기]
  호텔 전용 아크타입 풀 형성
  → 시뮬레이션 정밀도 향상
```

## 예상 공격 Q&A

| 공격 | 방어 |
|---|---|
| "LLM이 진짜 고객처럼 생각하냐?" | "훈련 없이 테스트셋에서 PR-AUC X.XX가 나왔습니다. LLM이 이 도메인을 이해하는지를 이론이 아닌 숫자로 보여드립니다." |
| "아크타입이 실제 고객과 다르면?" | "아크타입은 2년치 실제 예약 데이터에서 도출됩니다. 호텔 데이터가 쌓이면 그 호텔 고객으로 calibration됩니다." |
| "시뮬레이션 결과를 어떻게 믿냐?" | "정확한 수치를 주장하는 게 아닙니다. 할인율이 높을수록 수락률이 높아지는 방향성이 상식과 일치하는지를 확인하는 사전 탐색 도구입니다." |
| "500건으로도 충분하지 않냐?" | "세그먼트별(국적×채널×lead_time) 분포를 보려면 각 셀 최소 30건이 필요합니다. 20,000건이어야 통계적으로 의미 있는 분석이 가능합니다." |
