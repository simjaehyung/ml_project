## Slide 05 — Q1 증거 (취소 예측 + Flexi 시스템)

### 모델 성능 (실측값)

| 모델 | PR-AUC | 비고 |
|------|--------|------|
| Dummy (most_frequent) | 0.3870 | 이론값 ≈ test 취소율 38.7% |
| Logistic Regression | 0.7818 | |
| Random Forest | 0.7785 | |
| XGBoost | 0.8053 | |
| **LightGBM ★** | **0.8189** | **Bootstrap 95% CI: [0.8128, 0.8245]** |

- 상대 개선: 0.8189 / 0.387 = **2.116배** (Dummy 대비)
- 절대 개선: +0.4319
- 외부 벤치마크: 기존 호텔 취소 논문들은 ROC-AUC(0.87~0.955) 보고. **PR-AUC 수치를 보고한 선행 연구 없음** → 내부 비교만 가능

### 날씨 Ablation Study (2026-05-26 신규 실험)

| 조건 | PR-AUC | Bootstrap 95% CI |
|------|--------|-----------------|
| WITH weather (7개 피처) | **0.8189** | [0.8128, 0.8245] |
| WITHOUT weather | 0.8166 | [0.8107, 0.8222] |
| 차이 | **+0.0022** | CI 겹침 → **통계적으로 유의하지 않음** |

- **날씨는 도움이 되지만 미미함** — Phase 2 윈도우 확장 실험이 여전히 의미 있음
- 날씨 피처 top-20 등장: temperature_2m_max (15위), wind_speed_10m_max (16위), temperature_2m_min (18위)

### 피처 중요도 Top 5 (gain 기준)

| 순위 | 피처 | Gain |
|------|------|------|
| 1 | lead_time | 71,403 |
| 2 | country_grouped_PRT | 62,520 |
| 3 | total_of_special_requests | 29,285 |
| 4 | previous_cancellations | 28,070 |
| 5 | market_segment_Online TA | 21,037 |

### RevPAR 계산 (실측값)

**수식:**
```
baseline_rev = Σ ADR_i × (1 - cancel_prob_i)          # Flexi 없을 때 기대수익
flexi_rev    = rev_standard + rev_accepted + rev_declined
revpar_uplift = (flexi_rev - baseline_rev) / baseline_rev × 100
```

**결과 (threshold=0.60, n=50 파일럿):**
| 항목 | 값 |
|------|-----|
| baseline_rev | €1,074.1 |
| flexi_rev | €1,948.1 |
| rev_gain | €874.0 |
| **RevPAR uplift** | **+81.4%** |

**핵심 가정 (방어 포인트):**
- Flexi 수락 손님의 취소 확률 × 0.5 적용 (`FLEXI_CANCEL_REDUCTION=0.5` 하드코딩)
- n=50 파일럿 기준 — 전체 test set 결과 아님
- 기대 수익(expected revenue) 개선 수치이며, 실현 RevPAR 아님

### ⚠️ Walk Rate 주의사항

발표에서 "재배치율" 수치는 시뮬레이션 측정값 대신 **시스템 구조 설명**으로 대체:
> "Flexi 풀은 오버부킹 완충 역할. 임계값 0.60 기준으로 취소 예측 정확도가 충분히 높을 때 walk 발생을 최소화하도록 설계."

시뮬레이션의 39.5% walk 확률 수치는 n=50 단일 파일럿의 이론적 확률값이며, Phase 2에서 전체 test set 기반 재측정 예정(미결 항목 N5).

**예상 질문**
> "PR-AUC 0.819가 좋은 건가요?"
→ Dummy 대비 2.1배. 더 중요한 것은 Bootstrap 95% CI [0.8128, 0.8245]로 구간이 좁고 안정적. 임계값별 PR curve를 통해 운영 가능한 precision-recall trade-off 구간이 명확히 존재함.

> "날씨가 실제로 도움이 되나요?"
→ 소폭 기여(+0.0022 PR-AUC)하지만 통계적으로 유의하지 않음. 날씨 피처 3개가 top-20 내에 있어 모델이 활용하긴 하나, 주요 신호는 lead_time, country_PRT, special_requests. 윈도우 확장 실험(Phase 2)에서 더 강한 신호가 나올 가능성 있음.

## Slide 06 — Q2: 데이터 공백과 해법 (왜 LLM인가)

**왜 다른 방법은 안 되는가**
| 방법 | 문제점 |
|------|--------|
| 규칙 기반 | 개인차 반영 불가. B 아키타입 €50→65% 수락, €80→100% 수락 — 고정 금액은 과소/과대 보상 |
| 설문 | 가설적 응답 편향, 실제 압박 상황과 다름 |
| 전통 ML | 수락/거절 레이블 0건 → 학습 불가 |
| **LLM ✓** | 연구 문헌 기반 행동 시뮬 → 아키타입별 패턴 발견 가능 |

**인용 논문**
| 논문 | 핵심 주장 |
|------|----------|
| Aher et al. (2023). *Using LLMs to Simulate Multiple Humans* | GPT-4가 경제 실험(Ultimatum Game 등)에서 인간과 통계적으로 유사한 분포 재현 |
| Horton & Argyle (2023). *One Simulation, Many Simulacra* | LLM에 역할 부여 시 그룹별 행동 차이 재현. Normative hint 제거 방법론 근거 |
| Park et al. (2023). *Can LLM Already Serve as A Database Interface?* | LLM의 구조적 행동 패턴 시뮬레이션 가능성 |

**예상 질문**
> "LLM이 실제 인간 행동을 얼마나 잘 반영하나요?"
→ Aher 2023 근거. 저희는 이것을 정답이 아닌 **초기 디폴트값의 출발점**으로 포지셔닝. 실제 협상 데이터가 쌓이면 ML②로 대체.

## Slide 07 — Q2 결과 (1,240 runs, Clopper-Pearson 검증 완료)

### 실험 설계
- 총 실행: 5 아키타입 × 5~8 오퍼 구간 × 40회 반복 ≈ 1,240 runs
- hint 제거: normative hint 포함 시 ceiling artifact 발생 확인 → 제거 후 재실험
- 모델: Claude Sonnet 4.6

### Clopper-Pearson 95% CI 검증 결과 (n=40/시나리오)

| 아키타입 | 오퍼 (€) | 수락률 | CI 하한 | CI 상한 | 평가 |
|---------|---------|-------|---------|---------|------|
| **D** | **€29** | 0% | 0.000 | 0.088 | 구조적 영(零) |
| D | €33 | 0% | 0.000 | 0.088 | 구조적 영 |
| D | €37 | 0% | 0.000 | 0.088 | 구조적 영 |
| **D** | **€42** | **12.5%** | **0.042** | **0.268** | ⚠️ 방향 명확, 구간 넓음 |
| **D** | **€46** | **100%** | **0.912** | **1.000** | **✅ 강건 (하한 91.2%)** |
| D | €66 | 97.5% | 0.868 | 0.999 | 강건 |
| **B** | **€91** | **100%** | **0.912** | **1.000** | **✅ 앵커링 역설 — 강건** |
| **B** | **€99** | **0%** | **0.000** | **0.088** | **✅ 앵커링 역설 — 강건** |
| B | €49 | 65% | 0.483 | 0.794 | 충분히 검증 |
| B | €80 | 100% | 0.912 | 1.000 | 강건 |
| A | €62~216 | 100% | 0.912 | 1.000 | 전 구간 강건 |

### 통계적 유의성

| 비교 | 검정 | p값 |
|------|------|-----|
| B €91 vs €99 (앵커링 역설) | Fisher's exact | **< 0.000001** |
| D €29 vs €46 (step function) | Fisher's exact | **< 0.000001** |
| D €42 vs €46 | Fisher's exact | **< 0.000001** |

→ **앵커링 역설은 이 프로젝트에서 통계적으로 가장 강건한 발견.**

### 강건성 분류

**강건한 주장 ✅**
- A 아키타입 전 구간 100% 수락
- B 앵커링 역설 (€91↔€99 극적 반전, p<0.000001)
- D step function €46 임계값 (하한 91.2%)
- B €49 → 65% (CI [0.483, 0.794])

**제한적 주장 ⚠️ (방향 맞음, 구간 넓음)**
- D €42 → 12.5% : CI [0.042, 0.268]. n≥150이면 ±10pp 이내로 좁힐 수 있음

**구조적 한계 (실험 아티팩트)**
- C, E 아키타입 전 구간 0% : LLM이 어떤 금액도 수락 안 하는 경계 조건. 실제 확률 추정 불가
- B 앵커링 역설 자체가 LLM prompt anchoring artifact 가능성 — 통계적으로 유의하나 실제 인간 협상 검증 필요

### 예상 질문

> "1,240 runs로 통계적으로 충분한가요?"
→ 극단값 비교(0% vs 100%)는 n=40으로 충분 (p<0.000001). 중간 범위(50~70%) 비교는 n=40으로 underpowered (검정력 40~50%). 저희 핵심 주장은 극단값 패턴이므로 현재 샘플로 방어 가능.

> "앵커링 역설이 LLM 아티팩트 아닌가요?"
→ 가능성 인정. 통계적으로는 p<0.000001로 유의하지만, 이것이 실제 인간 행동 반영인지 LLM 텍스트 패턴인지는 검증 불가. Tversky & Kahneman (1974) 앵커링 이론과 일치하는 패턴이라는 점이 근거. 실제 협상 데이터 수집 후 검증이 목표.

> "hint를 제거한 이유가 뭔가요?"
→ D 아키타입 원본 실험에서 "높은 보상이 수락될 가능성이 높습니다" normative hint 포함 시 €99에서도 95% 수락. hint 제거 후 €42=0%, €46=100% — step function 회복. Horton & Argyle (2023) 방법론 준수.

## Slide 09 — 시스템의 본질 (데이터 수집 인프라)

**ML① vs ML② 비교**
| 구분 | ML ① | ML ② |
|------|------|------|
| 예측 대상 | P(취소 \| 예약피처 ~70개) | P(수락 \| 예약피처, 오퍼금액) |
| 학습 데이터 | Kaggle 78,703건 (train set) | 앱 협상 로그 (수집 후) |
| 현재 상태 | ✅ 구축 완료 (PR-AUC 0.8189) | 미구축 |

> 참고: LightGBM 입력 피처 수는 pd.get_dummies() 적용 후 **~70개** (CSV 컬럼 33개는 pre-OHE).

**Cold Start 구조**: 협상 이력 0건 → LLM 시뮬 디폴트값 사용(D: €46, B: ≤€91) → 앱 협상 기록 축적 → ML② 학습 → 이 호텔 전용 실시간 추천

**예상 질문**
> "ML②가 LLM보다 낫다는 근거가 있나요?"
→ "낫다"보다 "이 호텔에 특화된다"가 맞는 표현. ① 이 호텔 실제 협상 패턴으로 보정됨 ② LLM API 비용·지연 없이 실시간 추천 가능 ③ 매니저 최종 판단은 항상 필요 — "완전 자동화"가 아닌 "지원 고도화"가 목표.
